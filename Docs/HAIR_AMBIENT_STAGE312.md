# Stage312: Studio ambient shader input, seven-card regression

## Source diagnosis

The `KK_381623` game T-pose shows golden hair where the Stage311 Unreal frame has olive-grey shadow bands. The first hypothesis was the Shader Forge normal unpack: `Saved/ShaderDxbc/EC_Shaders/Shader_Forge_main_hair/0000.asm.txt` and `.../Shader_Forge_main_hair_front/0001.asm.txt` multiply sampled `_NormalMap.r` by `_NormalMap.a` before remapping XY. `KKPreviewActor.cpp` now follows those two pixel shaders for mapped normals. This is a shader-family rule, but it is **not** the explanation for the tested cards: all 436 `Shader Forge/main_hair` or `main_hair_front` material records in the local dump leave `_NormalMap` unbound. The 7-card, 42-frame `HairNormal312Final176` run loaded and passed renderer audits; the four new cards differ from Stage311 by at most 0.145 RGB levels per full-image channel, consistent with capture noise. It must not be reported as a hair-color fix.

The native Studio probe then sampled shader globals in the loaded `KK_381623` scene. `Saved/Tests/HairGlobals312Native177/Card0.json.shader-globals.tsv` records `_ambientshadowG=(0.5019608,0.5019608,0.5019608,1)`, `_LightColor0=(1,1,1,1)` and `_WorldSpaceLightPos0=(0,0.6427876,0.7660446,0)`. The first value agrees with the decompiled `Studio.SceneInfo` default `Utility.ConvertColor(128,128,128)` and `Studio.SystemButtonCtrl.SetAmbientShadow`: it sets global alpha to `1 - sceneInfo.ambientShadowG`. The local `UserData/config/system.xml` has `<shadowDepth>0</shadowDepth>`, so Studio sends alpha 1. The old extractor sent 0. `Manager.Character.UpdateGlobalShader` has a different non-Studio path; the preview's game-photo reference is Studio, so that path cannot supply this input.

`Shader Forge/main_hair` ForwardBase pixel shader `cb0[17]` is `_ambientshadowG` (confirmed from its Unity shader binding table). It consumes RGB and alpha in the shadow calculation, so the wrong global applies to every material of that shader family, independent of the card. Skin and clothes branches also read the same global. The exporter now sends `1 - configured Studio shadow depth`, and the three Unreal shader branches that modeled the global use the Studio default RGB 128/255. No card name, per-image color, or renderer index is used in this correction.

## Source ColorMask in the hair fragment

The `Shader Forge/main_hair` ForwardBase DXBC samples `_ColorMask` as `t3` using its independent `_ColorMask_ST` (`cb0[13]`), then blends `_Color`, `_Color2` and `_Color3` on each fragment before multiplying `_MainTex`. The old extractor instead baked `hair_get_diffuse` into an 8-bit PNG on the CPU. This changed where UV transform, bilinear filtering, and mips happen, and quantized the mixed result before the fragment shader. The source material's missing `_MainTex` is correctly replaced by a white texture **at ColorMask resolution** in `ParsedBundle`; the initial diagnosis that this specific card lost its 1024² mask by shrinking it to an 8×8 white fallback was false. The 8×8 fallback remains possible only when no source mask was resolved, and the new fragment path handles that case without shrinking an independent mask.

Hair and hair-shader accessories now retain their source `_MainTex` and `_ColorMask` as separate inputs. Their game and Material Editor colour overrides are stored as material properties; the existing three-colour UE shader node mixes the sampled mask in the fragment. Authored ColorMask sampling metadata is passed through the session cache and UE texture creator, and a Material Editor texture replacement invalidates that authored metadata. `SESSION_PIPELINE_VER=174` and the extract cache stamp invalidate older baked sessions. This logic keys on the shader family or source hair-renderer hint, never on a card name. It also keeps the item shader's separate four-colour path.
