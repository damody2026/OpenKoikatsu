# 街頭社交：自動遊玩測試計畫 v2（待 review）

v1 用「TTS 產生假玩家語音」；你提的新方向更好：**遊戲內加一條控制通道，用 MCP 暴露給我**，我就能像玩家一樣自己玩——
輸入文字給女主、按按鈕、走路、看畫面與狀態，邊玩邊判斷，而不是只跑死的劇本。

目標不變：在你玩之前，先把「玩 5 分鐘就會撞到」的明顯 bug 抓乾淨。
原則不變：**不瞬移、不跳時間、不呼叫內部捷徑**；一切走玩家真的會走的路（走路、按 E、說話、點按鈕、等待）。

---

## 1. 整體架構

```
Claude（我）
   │  MCP 工具呼叫（stdio）
   ▼
ok-game-mcp（Rust，Tools/ok-game-mcp，開發用小程式）
   │  HTTP，只綁 127.0.0.1:47870
   ▼
遊戲內「開發控制通道」（只有啟動參數 -StreetSocialControl 才開）
   │  指令排進佇列，在遊戲主執行緒的 Tick 裡執行（跟玩家操作走同一套程式）
   ▼
街頭場景（真的走路、真的點 UI、真的呼叫模型、真的 TTS 回覆）
```

安全：只綁本機、只在帶啟動參數時才開、正式啟動腳本不帶這個參數，所以你平常玩的版本沒有這條通道。

## 2. 遊戲端控制通道（要新寫的部分）

| 端點 / MCP 工具 | 做什麼 | 實作重點 |
|---|---|---|
| `state` | 回傳完整快照：遊戲時間、玩家座標與朝向、五位女主（座標、朝向、動作 clip、旗標 target/companion/outing/pair…）、談話對象、自由對話是否開啟、收音狀態與音量、購物車、餐桌（每道菜剩幾%）、錢包與欠款、目前提示訊息、可按的按鈕清單 | 全部讀現有狀態，不改行為 |
| `say <文字>` | 把文字當成玩家說的話，走 `SendFreeTalk`（跟打字送出、ASR 辨識完送出是同一條路） | 另有 `say_voice <文字>`：用本機 TTS 產生語音走 `/listen/inject`，專門測麥克風→ASR→VAD 這條路（少量） |
| `buttons` / `click <文字>` | 列出目前畫面所有可按的按鈕；照畫面上的文字按下（含右側面板、對話框、結帳選項） | 沿用現有 UI 探針「照文字找按鈕」的機制，補上列舉 |
| `key <鍵> [持續秒數]` | 模擬按鍵：E、F、Esc、數字鍵、WASD（持續按住）、Shift 跑步 | **關鍵改動**：把遊戲裡直接讀 `IsInputKeyDown/WasInputKeyJustPressed` 的地方（約十幾處）改成經過一個「虛擬輸入層」，真人與通道的輸入都走同一處，所以 WASD 走路是**真的走**，不會瞬移 |
| `look <yaw/pitch>` | 轉動鏡頭 | 虛擬滑鼠位移 |
| `navigate <女主N｜地點id>` | 啟動遊戲內建自動導航（玩家用正常速度、有碰撞地走過去） | 即現有「導航到她身邊」 |
| `screenshot` | 存一張含 UI 的截圖，回傳路徑；我可以直接看圖判斷（朝向、重疊、椅子、字幕…） | 沿用決策截圖機制 |
| `log [since]` | 回傳新增的日誌行（可用關鍵字過濾） | 讀 `game.log` |
| `violations` | 內建「自動檢查員」目前累積的違規（見第 5 節） | 每秒檢查，違規時自動截圖 |
| `wait <秒> [條件]` | 等待（例如等她回完、等 30 秒上菜）；MCP 端實作，遊戲照真實時間走 | 不加速、不跳時間 |

所有指令回傳「執行前後狀態差異」，我可以立刻看到按下去有沒有生效。

## 3. MCP 程式

- `Tools/ok-game-mcp`：Rust、stdio JSON-RPC，把上表轉成 MCP 工具；專案根目錄的 `.mcp.json` 註冊，Claude Code 打開專案就能用。
- 另有一個 `Tools/run_street_social_playtest.ps1`：啟動遊戲（帶 `-StreetSocialControl`）、確認 ASR/TTS 伺服器就緒、等待通道上線；你也能自己跑。

## 4. 我怎麼測（兩種並用）

**A. 探索式（我自己玩）**：像玩家一樣：走去找女主 → 按 E → 聊天 → 邀約吃飯 → 點菜 → 結帳 → 吃 → 道別 …，每一步看狀態與截圖，**用判斷力**找怪事（例如她前後說法矛盾、動作怪、畫面不對），這是 v1 劇本做不到的。

**B. 回歸式（劇本重播）**：把我探索時發現的問題固定成 JSON 劇本（`say/click/key/navigate/wait/expect`），之後每次改程式都可以重播，確認沒壞回去。

**時間**：真實速度。遊戲時鐘是**真實 1 小時＝遊戲 24 小時**，所以連續玩 60 分鐘就會自然經過早上、中午、晚上，餐廳 11–22 點營業、打烊、宿舍門禁、日夜光線都會發生。不使用跳時間，只在開局設一次起始時刻。

**分段（合計 ≥ 75 分鐘，每段可單獨重跑）**

| 段 | 時長 | 內容 | 重點 |
|---|---|---|---|
| A 基礎 | 10 分 | 走路找女主 → E 進自由對話 → 打招呼 → 話題（含經過自動撿取）→ 道別離開 | E 直接進對話、收音、朝向、道別離開、撿話題、右側面板捲動 |
| B 吃飯全流程 | 20 分 | 邀約 → 走過去 → 進店 → 看菜單 → 說/按鈕點餐、她自己點 → 結帳（我請/她請/各付/墊付）→ 30 秒上菜 → 吃（看 %）→ 吃不下 → 打烊 → 離開 | 點餐通知、請客承諾、墊付、餐桌 %、關店、拍照打斷、重疊、坐姿漂移 |
| C 外出同行 | 15 分 | `go:地點`（多處）、`stroll` 散步、被擋住、半路道別、說好卻不去 | 同行走不動、障礙物距離 ≥50cm、路線卡住、座標重疊 |
| D 社交邊界 | 15 分 | 沉默懲罰、換女主、別的女主走來、電話訊息、借錢、禮物、拍照、亂輸入轟炸、麥克風斷線 | 對話狀態機、重連、模型壞 JSON、UI 重建過頻 |
| E 浸泡 | 30 分 | 對五位女主輪流隨機玩，不重置遊戲 | 長時間穩定：記憶體/顯存/幀率、伺服器、存檔讀回、日夜交替 |
| V 語音路徑 | 10 分 | 少量用本機 TTS 產生玩家語音走 ASR（含插話、停頓、雜音、換麥克風） | ASR 辨識率、VAD 切句、收音恢復 |

## 5. 自動檢查員（遊戲內、每秒檢查，違規就截圖與記錄）

**畫面與動作**：談話中她朝向偏離 >20° 超過 2 秒；對話對象與玩家重疊（<45cm）且不在配對活動；坐姿動畫卻無坐姿活動／無椅子；同行時她 >3 秒原地不動而距離 >150cm；導航停住 >5 秒；散步路線上有點離障礙物 <50cm；UI 每秒重建 >4 次；右側面板捲動被重設。

**對話與經濟**：說了菜名購物車沒有（10 秒內）；結帳後購物車沒清；付款三方金額加總 ≠ 總價；墊付沒記欠款；她答應請客後仍是你付；打烊後仍能開始吃飯／活動沒結束；備餐中能吃；上菜後 % 沒下降；吃飽仍繼續吃；說再見 10 秒內沒離開對話；系統通知（含 `favor_delta`）出現在字幕或歷史；她口頭同意卻沒行動。

**系統**：ASR/TTS 行程存活且隨遊戲結束退出；麥克風 `listening` 持續為真、斷線 5 秒內重連；日誌出現 `Fatal/Assertion/ensure` 與未預期警告計數；幀時間 p99；記憶體/顯存成長；存檔讀回一致。

每條檢查員我都會用一個**故意製造的錯誤**驗證它真的抓得到，避免「沒報錯＝沒問題」的假象。

## 6. 產出

`Saved/StreetSocial/Playtest-<標籤>/`：`report.md`（時間軸、每個違規的嚴重度/時刻/重現步驟/截圖/日誌片段）、`fails/`（違規截圖＋前後 10 秒日誌）、`transcript.txt`（我說的話、她回什麼、她的 action，可看出模型前後矛盾）、`decisions/`、各段的劇本 JSON（可重播）。

## 7. 執行步驟

1. **P1 建工具（不玩）**：虛擬輸入層（改十幾處輸入讀取）→ 控制通道（state/say/click/key/navigate/screenshot/log/violations）→ `ok-game-mcp` → 啟動腳本 → 檢查員。
2. **P2 乾跑 15 分鐘**：驗證工具本身（走得動、點得到、檢查員不誤報、故意錯誤抓得到）。
3. **P3 正式測 A→E、V**，邊測邊記錄；發現問題立刻判斷是不是 bug（看日誌與截圖），不是就調整檢查條件。
4. **P4 修**：確定是 bug 的就修，固定成回歸劇本，重跑相關段落，直到 A–E 連續乾淨一輪。
5. 交付總報告＋重現方式（一行指令，你也能自己重跑）。

## 8. 限制與風險（先講明）

- **模型有隨機性**，同一句話每次回覆不同；問題以「違反不變條件」＋我看逐字稿判斷，不比對固定答案。
- **真模型花 token 與時間**（約每 10–20 秒一次，60 分鐘 200–400 次）。可選「假模型」模式（固定回覆、可重現、免費，專驗遊戲邏輯），建議兩種都跑。
- **跑的時候這台機器不能被你使用**（遊戲視窗要前景、佔 GPU、會出聲音）；若你想邊看邊玩，通道也能讓你和我同時看同一個畫面。
- 文字輸入**繞過** ASR/VAD/麥克風，所以那條路只由 V 段負責，覆蓋較少。
- 我只能抓到「走得到的情境＋寫得出的不變條件」，抓不到的新型態問題請你回報，我會補進檢查員與劇本。
- 輸入層改動會碰到十幾處既有輸入讀取，有風險引入回歸；改完會先跑現有 `*SelfTest` 與 UI 探針確認沒壞。
