# APNG 低模伴隨檔

2026-10-10：轉存 APNG 時，同時用 Instant Meshes 重網格產生同一角色的低模，含骨架與蒙皮權重。

## 產物

APNG 寫成 `X.png` 後，旁邊多兩個檔：

| 檔案 | 內容 |
|---|---|
| `X.lowpoly.glb` | glTF 2.0 二進位。單一骨架（共用 rig，C000 為 677 骨）、每個可見部件一個 mesh，帶 POSITION／NORMAL／TEXCOORD_0／JOINTS_0／WEIGHTS_0 與主貼圖 |
| `X.lowpoly.json` | 每個部件的處理方式、面數、補回的原始三角數與偏差檢查 |

APNG 本身不變。低模失敗只記錄錯誤，不影響已存好的卡。

## 觸發點

- Gallery「另存 APNG 新卡」：擷取前在遊戲執行緒複製目前（已套身形）的 session，卡片存好後在背景執行緒重網格，完成時在檢視面板與畫面訊息顯示結果，日誌 `APNG low-poly PASS` 或 `FAILED`。
- `ok.ExportApngCard`（批次）：存卡後同步輸出，日誌同上；低模失敗不改變程序結束碼。

C++：`FOkLowPoly::Capture` / `Export`（`KKRustExtract.h`）。C ABI：`ok_lowpoly_capture`、`ok_lowpoly_export`、`ok_lowpoly_free`（`ok_extract.h`）。

## 批次與百人房間

`Tools/ok-extract/target/release/ok-lowpoly.exe [--budget N] [--outfit N] [--report FILE] CARD.png|selection.json...` 以 APNG 匯出相同的程式輸出伴隨檔；`--report` 寫每張卡的面數與耗時。

另寫 `X.lowpoly.okmap`（`OKLPMAP1`）：每個重網格部件記錄原始頂點數、索引數與索引 FNV-1a 雜湊，以及每個低模頂點所在的原始三角形與重心座標（幾何／權重一組、UV 島一組）和低模三角形。

`CrowdRoom100.cmd`（原 `CrowdRoomDevelopmentAPNGGPU.cmd`）以 `-RuntimeLowPoly` 啟動百人房間。房間抓取每張卡的原始網格後，`OKApplyRuntimeLowPoly`（`KKRuntimeMesh.cpp`）依 okmap 用同一份 session 重建低模頂點：在畫出空間內插位置、法線、嘴／眨眼／表情 morph 與 palette slot 權重（保留最強 4 個 slot），再用與原始頂點相同的參考反矩陣與 21845 量化綁到 `__ok_palette` 骨。骨架、姿勢庫、GPU 快取都不變。部件以拓撲比對；比不上或蒙皮不可逆的部件保留原網格，日誌 `Runtime low-poly applied|skipped` 逐張列出。之後房間原有的 QEM 預算縮減照常執行。

2026-10-10 `Content/CharacterCards/CrowdAPNG/selection.json` 一百張卡、第 0 套服裝：全部成功，合計 9,103,908 → 2,868,578 三角（31.5%），每張中位數 27,344；20 張超過 28,000，最重 C010 833,361 → 89,775、C028 187,577 → 82,214（部分部件過不了品質門檻而保留原網格）。總耗時約 288 秒，單張最長 13.3 秒。報告 `Saved/Crowd/LowPolyR1.json`。

### 2026-10-10 下午：十張測試版

- 依使用者要求不再勉強減面：每個部件只按預算份額重網格一次，結果高於份額也照用，不再多輪壓低。
- 頭髮（hair shader 或名稱含 hair）不重網格：髮片會被重網格切碎，在房間裡顯示成黑色碎片；改交給房間原有的邊塌縮縮減，也不計入預算。
- 低模頂點先貼回原表面，再沿原法線外推到低模三角不低於原表面（每頂點偏移寫進 okmap，格式 `OKLPMAP2`）。各部件分別重網格時，弦會稍微切進彎曲表面，讓內襯或身體透出來；這樣可以避免。房間與 GLB 都套用。
- 破面處理（使用者回報「輸出四面體會破面」）：重網格本來就是三角模式（`-r 6 -p 6`），多邊形由重網格器依角度切耳成三角，沒有四邊形。破面來自：
  - UV 縫複製頂點的外推量各自計算，同位置的複本被推到不同位置，沿 UV 縫裂開。改為同一原始點共用一個外推量。C000 身體內部破洞由 38 個降到 12 個以下。
  - 重網格器不補 7 邊以上的洞：沿原始邊界（袖口、領口、裙襬）走的環當作真開口保留，其餘內部洞用切耳法補（環先拆成簡單環，限 128 點、需大致平面）。
  - 相鄰部件接縫（上衣與裙子在腰部）因各自重網格的邊界內縮而裂開：低模邊界點靠近原始邊界時吸附到原始邊界上。
  - 分層衣物（`X`、`X_g` 光澤層、`X_kazari` 滾邊、`X_ura` 內襯）只有各層重合時才正確，整組保留原網格交給房間的邊塌縮縮減。
  - 之後把補 7 邊以上的洞與邊界吸附移進重網格器（`Tools/vendor/instant-meshes/src/postprocess.rs`，預設開啟），低模程式不再自己做。C000 重網格器輸出：身體內部洞 2 → 0、邊界內縮最大 16.65 mm → 0，裙子 35.56 mm → 0，泳衣下身內部洞 19 → 2。最終低模（只合併縫、不丟三角形量）臉、頭髮、內衣、鞋子沒有多餘的洞，身體開口數與原始相同。
  - 結果：C000 房間正、側、背面擷取與原網格版本目視一致。
- 卡夫卡（C064）外套破碎：外套下擺重網格後碎成小片，但碎片仍貼著原表面，p95 12.3 mm 低於 2% 門檻而被接受。新增品質門檻「邊界增長」：低模邊界總長（不含補回的原始三角）加一個部件對角線，除以重網格輸入（焊接、去掉雙面重複層）邊界總長加一個對角線。乾淨的部件約 1.0（七張卡 63 個部件中位數 1.02），這件外套 7.47，C007 襪子 18.23。超過 1.75 就判定失敗，先加倍面數重試，仍失敗則保留原網格。十張卡因此多保留了外套、襪子、針織上衣、內衣、部分鞋子與飾品。房間實拍卡夫卡正、側、背面衣服完整。十張合計 1,630,520 → 724,339 三角。
- `CrowdRoom10.cmd`：`selection.json` 前十張卡（`Saved/Crowd/CrowdRoom10/selection.json`）。房間自我測試通過，十張都套用低模（日誌 `Runtime low-poly applied`），合計 1,630,520 → 706,348 三角（`Saved/Crowd/CrowdRoom10/lowpoly.json`，含未重網格的頭髮；房間再做邊塌縮縮減）。百人房間的其他 90 張卡仍是舊版 okmap（頭髮也重網格過），之後要用同一方法重做。
- 房間執行檔：`Saved/Interaction/CrowdRoom100Host` 以 `prepare_interaction_runtime_host.ps1` 建立後用 UBT 編 Game target，`Tools/stage_crowd_room100.ps1` 經 `stage_interaction_runtime.ps1` 放到 `Saved/StreetSocial/Build/CrowdRoom100-<tag>.stage` 並寫 `Saved/Crowd/CrowdRoom100/receipt.json`。

### 部件分類與各類預算（使用者規則，2026-10-10）

不用 AI，依 session 自帶的部件角色與 shader 分類（`lowpoly::category`）：

| 類別 | 規則 | 預算 |
|---|---|---|
| 臉 face | 角色 `head`：臉、眼睛、眼線、眉、牙、舌 | 不減面 |
| 身體 body | 角色 `body` | 每個部件 50%（`BODY_RATIO`） |
| 襪子 legwear | 角色 `clothes_socks`、`clothes_panst` | 不減面 |
| 頭髮 hair | 頭髮 shader（kind 1／10）或名稱、角色含 hair | 合計 30,000（`HAIR_TRIANGLE_BUDGET`） |
| 衣服＋飾品 outfit | 其餘 `clothes_*` 與 `accessory` | 合計 30,000（`--budget`，`DEFAULT_TRIANGLE_BUDGET`） |

- 頭髮與衣服＋飾品依類別內原面數比例分配；600 面以下與分層衣物先扣。類別已在預算內就不動。
- 品質門檻收緊：表面偏差 p95 ≤ min(部件對角線 0.75%, 5 mm)，加上邊界增長 ≤ 1.75。不過就面數加倍重試，直到原本的 70%，仍不過則保留原網格。之前 2% 門檻讓 C010 身體被壓到 424 面（p95 21 mm）而手腳碎掉。
- 身體不再沿法線外推（最內層，外推會穿出貼身衣物；C010 白長襪上出現粉紅條）。
- 每張報告 `classes` 列出各類原始／低模面數、預算與是否在預算內，部件列有 `class`。
- 十張結果：臉 9,228 都不動；身體約 16,754 → 8,200；超過 3 萬的頭髮減到 2.7–5.3 萬（品質門檻擋下太粗的版本，C068 133,275 → 53,246）；衣服＋飾品只有 C010 超過（766,134 → 76,101，八個 88,064 面的頸圈）。C068 房間實拍與原網格目視一致，頭髮沒有碎片。

## 做法

程式在 `Tools/ok-extract/src/lowpoly.rs`，重網格器以原始碼放在 `Tools/vendor/instant-meshes`（BSD-3，來源 `E:\Paper\instant-meshes-rs`，改動見該目錄 `VENDORED.md`）。

1. 骨架：用 session 的 `SkelExport`，也就是 Unreal 蒙皮用的同一份共用骨架。glTF 節點的區域變換是目前（含身形）姿勢，inverse bind 是 rest world。
2. 權重：
   - 身體／頭（skel_kind 1–3）：直接用已改名到共用骨架的骨索引。
   - 衣服、飾品、頭髮的私有 rig（skel_kind 4）：私有骨按名稱對到共用骨架；共用骨架沒有的私有骨（頭髮束、私有鏈）改掛最近的同名祖先，再不行掛 rig 的父骨。JSON 的 `skipped` 記錄這類骨數（C000 為 129 根）。
   - 無蒙皮的插座道具：權重 1 掛在跟隨骨上。
3. Rest 位置：每個頂點用它自己混合後的共用骨架矩陣，反算 session 目前畫出的位置。用同一組矩陣蒙皮回去就得到原來畫出的位置；衣服、身體、頭髮因此在匯出姿勢下互相對齊。四張卡每個部件最大誤差 ≤ 6×10⁻⁷ m。
4. 重網格：每個部件先依位置焊接 UV 縫，只用該部件實際畫到的頂點，去掉雙面重複三角，再以 Instant Meshes 重網格。參數相當於 CLI `-r 6 -p 6 -S 0 -c 30 -b -d`：直接輸出三角、不做 Laplacian 平滑、30 度摺痕、邊界對齊、決定性。選法見下方「重網格參數」。
5. 清理：離原表面超過兩倍平均低模邊長的低模三角（補洞時跨過髮束或布片的橋）丟掉；原網格中低模蓋不到的三角（比邊長細、被重網格吃掉的髮束、領尖）原樣補回，保留原本 UV 與權重。JSON 的 `patched_source_triangles` 記錄數量。
6. 屬性轉移：低模每個頂點取原網格最近點的三角形與重心座標，混合權重後取前四個再正規化。UV 從同一 UV 島取，跨縫的低模三角會複製頂點，不會拉過貼圖接縫；權重以位置決定，複製的頂點權重相同，不會裂開。
7. 法線與方向：每個連通塊依原網格法線投票決定繞序，法線用低模自己的平滑法線。
8. 材質：主貼圖原樣嵌入；`masked` → MASK、`translucent` → BLEND。身體的 clothes-over 遮罩（`_AlphaMask`、`_AlphaMask_ST`、`_alpha_a`／`_alpha_b`）烘進身體貼圖的 alpha，被衣服蓋住的皮膚不畫。全部雙面。卡片預覽本來就隱藏的 `o_dankon`、`o_dan_f`、`cm_o_dan00`、`cm_o_dan_f`、`o_gomu` 不輸出。
9. 座標：Unity 左手座標鏡射 X 成 glTF 右手座標，三角繞序同時對調。

## 面數

預設整人 28,000 三角（低於群眾低模 30,000 上限）。600 面以下的部件（眼線、眉、牙等）原樣保留；其餘按原面數比例分配。整人原本就在預算內時全部保留。

品質門檻：低模與原網格依面積均勻取樣的對稱距離 p95 不得超過部件對角線 2%，且面數必須比原本少。不過關先加倍面數重試，仍失敗就保留原網格，JSON 寫明原因。

Instant Meshes 的面數只是近似（薄而開放的網格會超出），所以會依每個部件自己實際產出的比例修正目標，最多五輪；較緊的目標失敗時沿用上一輪成功的結果。整體修正會讓身體替頭髮付出面數，所以不用。保留整塊原網格的部件無法壓低，頭髮很多的卡仍可能超出預算，`within_budget` 會標示。

## 驗證

`cargo test --release --lib lowpoly`：最近點 BVH 與暴力搜尋一致、權重混合正規化。

`OK_LOWPOLY_OUT=<目錄> cargo test --release --lib lowpoly::tests::installed_card_lowpoly -- --ignored --nocapture`（可加 `OK_LOWPOLY_CARD`、`OK_LOWPOLY_BUDGET`）以 UE 相同的環境變數載入真實卡：

- 每個部件反算後再蒙皮回去，與 session 畫出位置相差必須 < 0.1 mm。
- 每個重網格部件：`rest_deviation`（rest 姿勢）、`pose_deviation`（匯出姿勢）、`probe_deviation`（每根骨在匯出姿勢上再各自轉 25 度）。權重若轉移錯，probe 會遠大於 rest；測試要求 probe p95 ≤ 2 × max(rest, pose) + 3 mm。

## 限制

- 只輸出 APNG 當下選取的服裝與穿著狀態；其他服裝仍只在卡片內。
- 不含表情 blendshape；臉是匯出當下的表情。
- 不含動態骨模擬；共用骨架以外的私有骨改由祖先骨帶動，頭髮與私有鏈為剛性跟隨。
- 材質只有主貼圖；KK 的 color mask、ramp、法線貼圖、描邊不轉換，顏色與遊戲畫面會有差異。
- 部件分別重網格，緊貼的層（身體與緊身衣）在低模裡可能互相穿出幾毫米。
- 面數壓得低時，手指、腳趾會變成連在一起的手套狀；頭髮片重網格後加補回的原始三角，看起來比原本零碎。
- 細長或開放的小網格（鞋子、部分髮片）常過不了門檻而保留原網格。

## 錯誤與修正

- **衣服先被當成剛體**：初版只認 skel_kind 1–3 為蒙皮，衣服（skel_kind 4，私有 rig）落到單骨剛體綁定。修正為私有骨按名稱對到共用骨架。
- **兩套位置來源混用**：初版身體用 `SkelExport.part_rest`，衣服用目前畫出位置。實測 session 畫出的身體與 part_rest 蒙皮相差最多 3.4 cm（腳尖）、頭部約 1.2 cm，而且不是單純平移，兩者混用會讓衣服與身體錯位。改為所有部件都由目前畫出位置反算。
- **品質門檻用頂點計算**：p95 以頂點計，手指、腳趾頂點密，C001 身體被判 9.7 cm 而整塊保留；實際重網格外觀正常。改為依面積均勻取樣。
- **整體面數修正餓死身體**：五輪整體比例修正時，頭髮怎樣都壓不下來，C001 身體被壓到 2,204 面。改為逐部件依自身比例修正。
- **Workbench 截圖誤判**：Blender Workbench 不畫 alpha，`translucent` 疊層的格紋 RGB 露出，一度以為是 UV 轉移錯誤。改用 EEVEE 後與 APNG 一致；那件旗袍本來就是格紋。
- **重網格器在兩張卡上要求數十 GiB 記憶體**：C019 的補洞走訪在不含起點的迴圈裡無限前進；C033 外套的預先細分以平均邊長的兩倍為目標，把長三角切成上百萬份。補洞走訪改為最多 64 步（7 邊以上的洞本來就不補），預先細分長度下限為目標邊長的 1/4、頂點上限 16 倍輸入（256K–1M）。四張參考卡輸出不變，C033 由 105 秒降到 14 秒。記憶體配置失敗會直接終止行程，編輯器匯出這兩張卡也會當掉。
- **C064 外套卡死**：重網格器第 5 步（吸附與移除多餘邊）的兩層 `while changed` 迴圈在這件外套上來回振盪不停。改為內層最多 64 輪、外層最多 16 輪。
- **UE 編譯**：`UE_LOG` 不能直接放在不加大括號的 `if/else`；C++ 字串裡的 `\n` 在產生程式碼時被展開成真換行。兩者修正後 UE Development Editor 建置成功。
