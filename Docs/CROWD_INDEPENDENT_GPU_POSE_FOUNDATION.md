# Independent GPU pose foundation

The runtime compute API is in Plugins/KKCrowdGpuPacking/Source/KKCrowdGpuPacking/Public/OKIndependentGpuPose.h. It samples each actor's own two active clips, shortest-path quaternion interpolation, translation/scale interpolation, per-actor blend, hierarchy composition and inverse-bind multiplication. Tracks and keys need not be shared. Single-key tracks, arbitrary earlier parents, negative/nonuniform/zero scales are supported by this format.

Each key uses three float4s (48 bytes), with time in translation.w. This initial version is an explicit format/reference kernel, not a compact cooked codec. Matrices use three row float4s (48 bytes) and column-vector convention; convert Unreal row-vector matrices by transposing. A local bind-space transform must not be substituted for an inverse bind matrix.

The buffer overload accepts validated RDG resources, allowing future persistent external GPU buffers to be registered without reuploading immutable animation data. The batch overload uploads arrays for setup/oracle use. Persistent resource ownership, cooked animation export, real clip decode/retarget semantics, gameplay integration, current/previous buffers, conservative bounds and streaming are still to be implemented. Do not use the upload overload every gameplay frame or read matrices back for normal rendering.

Hierarchy evaluation currently walks ancestors independently for each output bone. This avoids inter-thread synchronization and shared-skeleton assumptions but repeats ancestor sampling. It is a correctness foundation, not the final performance architecture. Profile actual rigs before choosing level dispatches or another parallel hierarchy algorithm.

The synthetic oracle compares GPU float matrices with an independent CPU matrix-composition reference. It does NOT establish equivalence with Unreal's FTransform hierarchy composition, which can differ under rotated nonuniform scale, nor with imported affine three-bone rigs. Before real-card adoption, compare actual CPU poses/skinned vertices and implement the required semantics rather than changing tolerances or assuming matrix multiplication is interchangeable.

Run from PowerShell:

    & Tools/run_independent_gpu_pose_oracle.ps1 -Tag FreshTag

This builds an isolated precompiled-Engine editor test host in Saved/Crowd/IndependentGpuPoseHost. It never rebuilds/replaces authoring Editor Engine DLLs or enables the feature in the crowd scene. First shader compilation may take time; test setup time is not game loading evidence. The owned process is hidden, bounded and recorded by PID. -SkipBuild reuses the isolated snapshot and must not be used to validate changed source.

The oracle uses 100 synthetic independent rigs (3-19 bones), two independently keyed clips per rig, varied phase/blend, shortest-path quaternion signs and rank-deficient/negative scales. It rejects seven malformed input batches before dispatch. The 0.0005 absolute matrix-element tolerance is for these small synthetic transforms only, not a real-card acceptance threshold. Reports explicitly mark synthetic_only=true and fps_evidence=false. No current game visuals or defaults change.

## Real private animation preparation and native hierarchy (RealVerticesR1)

Implemented a read-only real-card preparation/oracle mode in Tools/GpuPoseAudit. It loads each selected low character's existing private compressed walk, accepts non-additive Bitwise ConstantKeyLerp/linear clips with constant-or-common-uniform channel grids, copies each actor's own keys/tracks and retains constant tracks as single keys. It does not create a shared skeleton/pose, overwrite source assets or enable gameplay GPU poses. Unsupported formats/grids/dimensions report a rejection; they are not resampled silently. Future cooked export/loader still needs versioned persistent assets and more channel-grid/codec coverage.

The installed codec uses shortest-path normalized linear rotation interpolation, not slerp. Added a per-track interpolation mode so native clips use that behavior while the existing synthetic slerp path remains explicit. Native hierarchy mode now follows the actual FTransform root-to-leaf composition. Positive-scale operations use quaternion product, component-wise scale multiplication and rotated/scaled translation. Either input containing a negative scale uses matrix product, axis normalization, desired sign restoration and quaternion reconstruction; zero axes produce identity rotation as in the native implementation. No card-specific branch or numerical tolerance relaxation was used.

RealCardR1/R2 exposed a hierarchy error: local sampling max 0.0000534 but matrix-product component poses differed by 2.480892. Native hierarchy fixed the single-card result (RealCardR3 max 0.00008392334). RealTenR1 exposed an arbitrary 4096-total-bone guard; RealTenR2 exposed negative scale. These failures are retained in their reports/error log. Total actor capacity is now up to 65536 bones with index/depth validation; per-section limits were not increased. Native hierarchy depth is currently bounded at 256, and future consumer/dispatch limits must be validated before gameplay integration.

RealTenR3 passed ten actual distinct prepared cards, individually offset playback phases and six time samples including both endpoints: 1,786,320 compared matrix elements, max 0.000126361847, RMS 0.000003180004, all finite. Largest tested private skeleton has 4367 bones. NativeRegressionR1 actual GPU dispatch also passed the 100 synthetic actor oracle, now mixing matrix/native hierarchies and negative/zero scales: max 0.0000677108765, seven malformed inputs rejected.

Added editable low-vertex validation using each low outfit part's actual positions, positive weights and mesh inverse-bind matrices, with clip-skeleton bone-name mapping. RealVerticesR1 final build/GPU run passed the same ten independent characters at six individual times: 1,372,332 vertex comparisons, max position error 0.000147656378 cm versus a predeclared 0.01 cm gate; the matrix gate remained 0.001 and passed. This compares predicted skin positions from GPU matrices against the native compressed-codec/FTransform reference. It is not a rendered image comparison and does not verify final render vertex packing, normals/tangents, near parts, retarget/root-lock/morph behavior, previous-frame matrices or shadows.

Ten clips contain 73,541,412 source compressed bytes; the explicit float-key preparation uses 115,136,880 key bytes before tracks/bindings/tasks. This is a correctness-stage format with measured expansion, not a compact-loading or <60-second guarantee. Oracle uploads/readbacks are diagnostic only and cannot establish runtime FPS. Next work must produce immutable cooked GPU data and persistent resources, then integrate current/previous palette output into the low/near rendering path with CPU fallback and bounds; do not adopt a per-frame CPU key preparation or full-data upload.

## Persistent GPU residency and pose history (ResidentFinalR1 / RealResidentR1)

Implemented FOKResidentGpuPose in the packing plugin. The render-thread owner promotes immutable keys, tracks, actor layout, output tasks and inverse bindings into pooled GPU buffers once per generation. CPU retention is limited to clip ownership/layout metadata and last playback parameters. Evaluate registers those buffers with RDG and uploads 16 bytes of time/blend parameters per actor; changing animation IDs also uploads the actor-selection table (16 bytes per actor). The core pass does not read matrices back or prepare keys per frame. The supplied times can be computed from each actor's own phase/rate; no common pose or animation is substituted.

Current and previous matrices are returned as GPU buffer references. First evaluation, an explicit history reset and identical held poses return current=previous; an advancing pose references the prior evaluated buffer. Motion consumers must also maintain previous world transforms separately. Exact repeated playback parameters skip uploads and compute. Initialize/release advance a generation token, and stale tokens, duplicate/backward frame IDs, invalid clip IDs/blends and cross-actor overlapping track ownership are rejected. Clip compatibility and dispatch capacity are checked before resource creation. Execute each graph before the next evaluation/reinitialization/release. Graph lifetime owns references needed by in-flight work. The synchronous readback helper is diagnostic only; it executes initialization uploads even when evaluation is rejected.

Final isolated build succeeded (RealResidentR1). ResidentFinalR1 uses the same verified source snapshot and passes actual DX12/SM6 dispatch with 100 synthetic independent rigs, each owning 20 different keyed clips. Six test frames cover independent selection, A/B blending, history, an unchanged held pose, history reset, resource release and reinitialization. Maximum current/previous matrix error is 0.0000953674316 against tolerance 0.0005. Two initializations upload 3,022,240 immutable bytes each; five compute evaluations and one reused frame upload 12,800 parameter bytes altogether. Six malformed playback/lifecycle requests are rejected. These 20 clips are synthetic coverage, not 20 real walk styles.

RealResidentR1 passes ten actual private character rigs at six independently offset times. One initialization uploads 117,121,840 immutable bytes. Six evaluations upload only 960 parameter bytes altogether (10 x 16 x 6), with no additional immutable upload. Current and previous pose errors both peak at 0.000126361847 against tolerance 0.001. All 1,372,332 editable low-vertex comparisons pass; maximum position error remains 0.000147656378 cm against the unchanged 0.01 cm gate. The separate local-pose diagnostic is intentionally skipped in resident mode to avoid an unrelated full-data upload; it remains available in legacy real mode. Source assets were not modified.

## GPU skin palette and renderer-format output (SkinPaletteFinalR1)

Added OKGpuSkinPalette.h/.cpp and SkinPalette.usf. Each mesh retains its own bone-name mapping and inverse-bind matrices; items select component-pose indices and write arbitrary destination palette indices. The compute pass directly composes component pose * inverse binding in column-vector convention and writes transposed float32 3x4 rows into a typed uint4 UAV, matching UE's uncompressed FCompressedBoneTransform memory layout. It handles current/previous poses in the same dispatch without TRS decomposition or CPU matrix uploads. Half/compressed transform consumers are explicitly outside this API's contract.

Bindings/mappings are initialized once as pooled GPU buffers. Pose and palette generation IDs prevent stale resources being mixed. Validation covers dimensions, dispatch capacity, finite bindings, source/destination bounds, duplicate destinations, buffer layout/capacity, overlapping current/previous regions and source/output aliasing. The API can write into an existing renderer transform buffer at caller-supplied row offsets; actual provider registration and component ownership/bounds/LOD integration are still pending. It is not yet connected to the gameplay scene.

SkinPaletteFinalR1 isolated build and GPU execution pass ten actual private rigs across six independently offset playback times. Coverage: 45,834 palette entries, including all low meshes' full bone arrays and 593 real render sections' BoneMaps; 6,600,096 current/previous palette-element comparisons against native inverse-bind * component FMatrix44f followed by StoreCompressedBoneTransform. Max matrix error 0.000126361847 <= unchanged 0.001 gate. The GPU-produced render-format palettes also pass all 1,372,332 original-position low-vertex comparisons, max 0.000147656378 cm <= unchanged 0.01 cm gate. The palette uploads 1,677,120 immutable bytes once; six dispatches add no palette metadata uploads. Pose parameters still total 960 bytes. Failed evidence is never overwritten. ## Versioned shader-data cache and worker loader (AnimationCacheFinalR2)

Added OKGpuAnimationCache.h/.cpp. Format version 1 has a fixed 60-byte header (magic/version/layout, payload length, expected source identity and payload SHA1), a bounded count table and explicit 16-byte key/track/actor/task/binding/palette arrays plus per-actor owned clip offsets. The format requires little-endian float32 layout. The caller supplies a source identity covering the relevant character/clip/mesh content, LOD/export configuration and interpretation/version. SHA1 detects stale/corrupt data; it is not an authenticity mechanism. This is shader data, not a complete gameplay manifest: per-card asset IDs, clip durations/root-motion/bounds/near mappings and cooked packaging still need their own integration.

Encode/decode/load/save validate pose ownership, palette correspondence, finite data, indices, topology and counts. Factored OKValidateOwnedGpuPose out of render-thread initialization so both cache and GPU initialization use the same validation. Byte budget defaults to 512 MiB per cache chunk, capped at the TArray index limit. Decoder verifies fixed header, exact payload size, checksum and total array byte count before allocating arrays. The file loader opens a reader and bounds its actual size before allocation, avoiding a separate FileSize/read race. Load failures leave caller data unchanged. Writer uses a unique temporary file and publish-without-replacement; existing immutable evidence/cache files are retained. Temporary cleanup affects only that writer's exact generated file.

OKLoadGpuAnimationCacheAsync captures path/identity/budget by value, reads/checks on the ordinary Unreal thread pool and returns movable owned data plus error/load duration. No UObject resolution, animation decompression or GPU command submission occurs in this loader. Gameplay consumers must check their actor/selection generation before adoption and must not block their frame loop on the future. The oracle consumes the future only in a diagnostic run and asserts execution outside Game/Render threads.

AnimationCacheFinalR2 final isolated build/GPU test passes ten actual private rigs. It exports to a new .json.gpuanim file, discards the prepared shader arrays, reloads on a worker and verifies bit-identical re-encoding. GPU evaluation/palette output uses the reloaded arrays. Six independent phases, 593 section BoneMaps, 6,600,096 current/previous palette elements and 1,372,332 low-vertex comparisons pass. Max palette error 0.000126361847; max vertex error 0.000147656378 cm; original gates remain unchanged. One-time palette/pose uploads and 960 bytes of subsequent pose parameters are unchanged.

Eleven rejection tests pass: truncated header, wrong version, wrong expected identity, payload corruption, byte-budget exhaustion, trailing bytes, recomputed-checksum impossible counts, recomputed-checksum invalid palette index, recomputed-checksum invalid clip ownership, existing immutable file and missing file. Failed decode preserves sentinel output. Current cache size 118,799,304 bytes; worker read/check duration in this diagnostic run 481.9177 ms. This freshly written/warm-cache measurement does not include full scene load, source import, GPU readiness or gameplay, and is not a cold/random-100 load guarantee or a native-loader performance comparison. Float-key expansion has not been compressed away.

CacheOwnerRegressionR1 uses the final built snapshot and confirms the shared ownership-validator refactor preserves the 100 independent synthetic actors x20 clips resident oracle, including release/reload/history and invalid lifecycle rejection. Source assets, all original outfits, authoring Editor Engine DLLs and staged Development defaults were not modified.

## Actor/clip/mesh manifest and arbitrary selection composition

Added OKGpuAnimationManifest.h/.cpp. A versioned, checksum-protected bounded binary sidecar links to the expected shader-cache identity. It records character IDs, full component-pose spans, each actor's owned clip IDs/track offsets/durations, per-part IDs and soft mesh paths, mesh-wide palettes and individual render-section palette ranges. No hard UObject references are introduced. Decoder validates header/identity/checksum, UTF8 lengths/counts, structural IDs and trailing bytes before adoption. Decode alone is structural; Validate against the loaded shader cache is mandatory before GPU use.

Validation checks actor/clip correspondence, component task order, identity task bindings (unbound component poses), key-time coverage by each clip duration, all palette range bounds/ownership/coverage, duplicate IDs/overlapping ranges, and that section entries use bindings from their own full mesh palette. Items can arrive in any order; destination indices determine lookup. This remains GPU binding metadata, not complete character/gameplay reconstruction: transforms, baked bounds, root-motion/curve policies, low/near transition and unsupported-component handling still require integration.

OKSelectGpuAnimationActors extracts arbitrary unique actor indices into an independently owned cache, copies each actor's clip/keys/tasks/bindings, and remaps each mesh/section palette. It preflights a conservative raw-data byte budget. OKComposeGpuAnimationCaches accepts independent chunks in chosen order and rebases key, track, actor, pose-task, inverse-binding and palette indices plus every manifest range. It rejects duplicate character IDs, invalid input manifests and byte-budget exhaustion; failures preserve existing outputs. No cross-character pose, skeleton, key or private binding deduplication is assumed. Chunk identities and selection order produce a derived identity; consumers still validate the source/package identity chain before adoption.

AnimationManifestFinalR1 isolated build/GPU run passes ten actual private character rigs. The manifest is saved/reloaded beside the cache and re-encodes bit-identically. The test partitions characters into reverse odd/even selections and recomposes them in a different order. At each character's independent intermediate phase, all current/previous component poses and full-mesh/section render-format palettes compare against the original native CPU reference: 1,695,456 element comparisons, max 0.0000762939453 <= unchanged 0.001 gate. Six malformed binary records, six semantic identity/range/duration/ownership cases, two invalid selections and two invalid composition requests are rejected (16 total), with sentinel outputs retained. The existing six-phase real pose/skin/vertex/guard tests also pass unchanged: 593 sections, 6,600,096 palette elements and 1,372,332 editable low vertices.
