## 目標與約束

在自建街道、runtime APNG 男主與五名女角上完成可遊玩的話題循環：取得、保存、選擇、女生出題、回答、效果、消耗、次日恢復，以及交談中部位互動。算法按 personality 與關係查共同資料，不按人物卡名稱特判。共同原作語音可預先整理；卡片的網格、姿勢、表情仍走 runtime。百人性能驗收本輪不處理。

## 實作順序

1. 核對原作 TopicDropData、TalkScene.CommandWait / AddDroppedTopics、Info.GetTouchVoice。保留原作稀有話題同類回答使用 rare[2] 的規則。把 Touch / See 各關係、部位與重複階段的原始文字、語音、表情、favor / lewdness 整理成共同資料。
2. 保留現有 48 種拾取、每日防重複、99 上限、話題袋、稀有話題使用紀錄、興趣加成、女生最近五次出題排除、精確／同類／錯誤／敷衍回答。補對話取得話題與庫存提示；獲得、消耗與關係效果須同一原子存檔。
3. 實作交談觸控／注視模式與部位選擇，提供頭、臉頰、左右手、左右胸等原作部位。觸控可在語音播放期間觸發；必須先取消舊的 speech / action epoch 與未提交話題、關係預覽，不消耗被中止的話題。不准兩段語音同時播放或舊語音完成後誤提交。
4. 第一次／第二次／第三次以後分別使用原作 reaction index 0 / 2 / 1；左右同類部位共用計數，重新交談重置。按初識／朋友／戀人選來源 stage 0 / 1 / 2。反應語音完整播放後才提交來源效果及一次交談成本；取消、角色失效、語音失敗不提交。
5. 使用現有 runtime 表情與嘴型播放觸碰反應；不冒充目前共用 gesture 為原作每行 pose。按共同骨骼語義建立可點擊部位，避免人物卡專用 collision 資產。部位按鈕必須可用，空白區點擊不能誤觸。
6. 增加純規則測試、實際 Development runtime 互動與取消驗證，獨立核對來源語音 hash 與效果，更新啟動 receipt。完整人工視覺、實際滑鼠／觸控操作、聽音與長時間驗收留到最後。

## 差異與資料邊界

自建街道的拾取物位置不是原作地圖。APNG 沒有原作 Heroine.isVirgin，不能從外觀推斷；目前情色話題按使用者指定提供。神社祈禱加成及原作地圖設施不偽裝已存在。五個測試 personality 的共同語音須全部有來源，其他 personality 依同一匯出／查表算法扩展；缺資料應明確拒絕，不套別人的聲音。
