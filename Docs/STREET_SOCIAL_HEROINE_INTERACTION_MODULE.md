# StreetSocial 女主互動模組（重構計畫）

日期：2026-10-12
狀態：P0–P5 已完成（2026-10-12），結果見文末「完成紀錄」。

## 為什麼要重構

和女主的互動現在散在約 20 個檔案裡：Scene.cpp、Mind、Lover、Life、Invite、Invitations、Outing、Economy、Venture、Bank、Finance、PhoneInbox、Contacts、Appointments、Encounter、Director、Campus 等。

每一處都自己做了一部分流程，所以同一件事出現好幾種做法，盤點時發現的錯誤大多來自這裡：
- **判斷她答不答應**：有些用 `PanelConsent`，有些用自己的門檻。
- **改關係數值**：每處各自 `CommitStore`。
- **寫紀錄和記憶**：有的有寫，有的沒寫。腳本話題、觸碰、告白、升朋友都沒寫，所以每天自動升朋友的條件達不到，她的 AI 也不知道你告白過。
- **謠言**：有的會產生、有的不會，可信度也沒有寫回。
- **按鈕**：散在各個面板。有些動作的規則寫好了，卻沒有按鈕，例如膝枕、躺下、喝酒。
- **規則和實際行為不一致**：例如回請時 AI 被告知「你堅持你付」，結帳卻沒照做。

## 目標

所有「你對她做的事」和「她對你做的事」，都走同一條流程：

```
互動請求（誰發起、對誰、哪種互動、參數）
  → 1. 能不能做：關係階段、數值門檻、地點、時間、金錢、她現在在做什麼
  → 2. 她願不願意：邀約判斷、尷尬度、被拒冷卻、纏人懲罰
  → 3. 她的反應：配合 / 害羞 / 刺激 / 抗議 / 拒絕
  → 4. 數值變化：好感、11 個情感軸、需求；重複做會遞減。一次寫入存檔
  → 5. 紀錄：她的互動紀錄 history，加上 AI 記憶（每一種互動都寫）
  → 6. 社交後果：謠言（公開 / 秘密 / 無，含可信度）、旁觀者的記憶、嫉妒
  → 7. 演出：動作、兩人合拍、走到某處、對話框、手機通知
  → 8. 結果：成功與否、理由、她要說的話（給對話和 UI）
```

規則都放在一張「互動表」裡，新增或調整一種互動只要改表。

## 模組結構

| 檔案 | 內容 |
|---|---|
| `OKStreetHeroine.h`（新） | 純資料與純函式，不依賴場景，可以寫單元測試。內容如下 |
| `OKStreetSocialHeroine.inl`（新） | 場景端的唯一入口和女主面板，內容如下 |

**`OKStreetHeroine.h`**
- **互動種類**：`EOKHeroineCat`，分為交談、觸碰、動作、活動、邀約、禮物、金錢、手機、關係、校園。
- **互動定義** `FOKHeroineAct`：
  - id、名稱、分類
  - 誰可以發起（你、她、兩者）
  - 門檻：最低關係階段、各軸下限、地點隱私、是否要當面
  - 邀約難度：沿用 `Invite.h` 的 6 級
  - 數值效果表，依反應分開；重複遞減規則
  - history 的種類和文字範本、記憶的重要度
  - 謠言種類
  - 演出代號
- **互動表** `OKHeroineActs()`：目前 DoAct 的 12 種、觸碰的 6 個部位、腳本話題的 3 類、告白、升朋友、分手、送禮、請客、借錢、托付、各種活動與邀約、一起讀書、股票建議、預言、打電話、傳訊息。
- **純函式**：
  - `OKHeroineGate(關係, 互動, 情境) → 允許/理由`
  - `OKHeroineReaction(關係, 互動, 尷尬度, 擲骰) → 反應`
  - `OKHeroineEffects(關係, 互動, 反應, 今天第幾次) → 各數值變化`

**`OKStreetSocialHeroine.inl`**
- **唯一入口**：`FOKHeroineResult Interact(int32 女主, FName 互動, const FOKHeroineArgs& 參數)`，跑完上面 8 步。
- **女主面板**：`BuildHeroinePanel()` 依互動表和門檻列出現在能做的事。
  - 原本散在各處的按鈕都改從這裡出：交談中的話題、身體互動、邀約、禮物、金錢、手機。
  - 做不到的不顯示，或顯示為灰色並說明原因。
- **其他系統的接法**：
  - AI 回覆裡的 `act`、`action`、`lend` 等，也改呼叫 `Interact`，並標記發起人是她。
  - 她主動做的事（Initiative、走過來、打電話、介紹朋友），一樣呼叫 `Interact(..., 發起人=她)`。

**不搬的部分**：日程、需求、商店型錄、銀行與股市（Rust）、校園學籍、動畫播放本身，都留在原處。互動模組只是呼叫它們。動畫播放（Lover、Pair）也留著，由模組在第 7 步發出請求。

## 分階段

每階段都盡量不改變原本的玩法，只修列出的錯誤。每階段結束都要通過：UE 自動測試（含 LongRun）、Rust 測試，加上一組新的遊戲內探針。

| 階段 | 內容 | 順便修掉 |
|---|---|---|
| P0 骨架 | `OKStreetHeroine.h`、`Interact()` 的 8 步、互動表的格式、單元測試 | — |
| P1 身體與交談 | DoAct 的 12 種、觸碰、腳本話題 1/2/3、撿話題／請她選話題、告白、升朋友、分手都改走 `Interact` | 這些都寫進 history 與記憶，每天自動升朋友的條件恢復正常 |
| P2 金錢 | 請客／誰付錢、送禮、借錢、托付與翻身、公司聘用、股票建議、預言、一起押彩 | AI 說「你堅持你付」時真的照做 |
| P3 活動與邀約 | 活動表、出遊、語音邀約、過夜、一對一、更親密、約定（準時、遲到、爽約、取消） | 統一用 `PanelConsent`；帶女主訂位或接送卻爽約時，店家同樣列黑名單 |
| P4 手機與她主動 | 訊息、電話、她主動聯絡；Initiative、走過來、偶遇與謠言 | 移除舊的「電話呼叫戀人」；謠言可信度寫回 |
| P5 面板 | 所有互動按鈕改由 `BuildHeroinePanel` 產生 | 補上膝枕、躺下、喝酒、餵食的按鈕；「女角數值」除錯面板只在開發模式出現；清掉死碼 |

P5 之後可以接著做：膝枕的真正動作、活動中的親吻和擁抱演出、分手後的和好流程、女主之間的爭風吃醋事件。

## 風險與做法

- **多人同時改同一批檔案**：另一個工作階段正在改公司相關的檔案（`OKStreetSocialCompany*.inl`、`HeroCompany.inl`）。
  - 公司聘用放在 P2 的最後，先避開那幾個檔案。
  - 每次只改當階段要遷移的呼叫點，舊函式保留成「轉呼叫 `Interact` 的薄包裝」，讓別人的程式不會壞掉，等穩定後再移除。
- **行為回歸**：P0 先為現有規則補單元測試（門檻、反應、數值），遷移後必須得到同樣的數字。
- **存檔相容**：只新增欄位，不改既有欄位的意義；history 的 kind 沿用現有名稱，再加上新的種類（`topic`、`touch`、`confession`、`stage`）。

## 完成紀錄（2026-10-12）

模組實際的樣子：
- `OKStreetHeroine.h`：互動表 `OKHeroineActs()`，以及門檻、門檻懲罰、反應數值等純函式。
- `OKStreetSocialHeroine.inl`：
  - 唯一入口 `Interact()`，依序是門檻 → 同意 → 反應 → 數值 → 紀錄與記憶 → 謠言 → 演出。
  - `HeroineNote()`：數值已由原處算好的互動，只寫紀錄和謠言，文字照原句。
  - `HeroineCheckoutLean()`：決定誰付錢。
  - `BuildHeroinePanel()`：女主面板。
- 單元測試：`Tests/OKStreetHeroine.spec.cpp`（Gates、Values、RumorConfidence）。
- 探針：`OK_STREET_UI_PROBE=heroine`，36 步全部通過。

| 階段 | 做了什麼 |
|---|---|
| P1 | DoAct 改成呼叫 `Interact`。原本的 LoverGate 改為互動表，門檻數字不變，有單元測試逐一比對。腳本話題、撿到的話題、觸碰、告白、升朋友、分手都寫進 history 或記憶；`topic`、`touch` 這兩種也算進「每天有聊過」的天數。分手會產生公開謠言。 |
| P2 | 請客、送禮、借錢、托付與翻身、公司聘用、股票建議、下單、預言、一起看盤、一起買彩券和競技彩，都改由模組記錄。請客和送禮的謠言改由互動表產生。她說要回請時，之後 6 小時內的結帳和活動付款由她付（她的錢不夠時例外）。 |
| P3 | 「更親密」改用和所有邀約相同的 `PanelConsent`（歸為私密房間類）。活動、邀約被拒、纏人、出遊、午睡和過夜、親密、約定、赴約、爽約都改由模組記錄；過夜和親密是秘密謠言。帶女主訂位或接送卻爽約時，店家同樣會列入黑名單。 |
| P4 | 移除舊的「電話呼叫戀人」（她走過來的那套），聯絡女主改用手機。名單只剩「導航」和「一對一」兩個按鈕，聯絡人自我測試和發布檢查也一起更新。謠言記下每個聽到的人有多確定（存在 `heard` 欄位）；轉述時依轉述者的確定度再打折，她的提示詞也依自己的確定度寫「確定／聽說／不太確定」。 |
| P5 | 女主面板的按鈕改由 `BuildHeroinePanel` 依互動表產生，只顯示目前關係階段做得到的。補上膝枕、一起躺下、一起喝酒（喝酒只在可飲食的地方出現）；餵食沿用背包裡的「餵她」。「女角數值」面板平常不顯示，按 F10 或設 `OK_STREET_DEV=1` 才出現。清掉的死碼：Finance 的 `if(false)` 舊股票區塊、BeginPair 重複的檢查、沒有被呼叫的 `FreeTalkVoice`。 |

沒有跑的：`test_street_social_runtime.ps1 -ContactsOnly`。它會開 15 次高模一對一場景，聯絡人自我測試這次只改了「按鈕從三個變兩個」和「拿掉電話呼叫的步驟」。

## 貞操與好感（2026-10-12 新增）

- **貞操值** 0～100，每位女主各有一個，存檔欄位 `chastity`。
  - 沒設定過時，依個性算出：30 + 0.3×害羞 + 0.3×魅力抗性 − 0.2×公開大膽，限制在 5～95。
  - 規則寫在 `OKHeroineDefaultChastity`、`OKHeroineChastity`（`OKStreetHeroine.h`）。
- **獨處**（一對一場景、「更親密」），由 `AloneConsent` 判斷：
  - 戀人：照原本的邀約規則。
  - 非戀人（含陌生人）：她的抗性 = 0.6×貞操 + 0.4×魅力抗性，朋友再 −10。你的魅力（外表）超過她的抗性時，她答應的機率是 50%～95%；沒超過就拒絕，並說出雙方的數字。
  - 朋友好感超過 100 時，答應機率至少 70%～95%。
- **好感上限**：朋友最高 200，戀人 150。
- **陌生人的好感上限**：每位女主各自不同，在 10～100 之間，代表她的攻略難度。
  - 存檔欄位 `stranger_cap`。
  - 決定方式：她的設定檔若有 `traits.difficulty` 就用這個值；沒有的話，用 10 + 0.5×魅力抗性 + 0.4×貞操（`OKHeroineStrangerCap`）。
  - 目前五位女主是 56～76。
  - 判斷上限一律用 `OKStreetFavorLimitFor`，它會依女主本人決定上限。
  - 陌生人好感一到上限就自動變成朋友（`TickAutoFriendship`）：寫入她的紀錄，畫面提示「成為朋友了」，好感照原規則歸零。如果她正是你在聊天的對象，等她這句話說完、語音也播完，她會用自己的個性開心地說幾句成為朋友的話（`HerSaysNext`）；你打到一半的字會保留。
- **告白**：
  - 好感 70～100：照原本的機率曲線。
  - 好感超過 100：成功率 80%，到 200 時為 100%。
  - 成功：關係變成戀人，好感設為 50。
  - 失敗：好感 −50。
- **女主數值面板**：右側按鈕「女主數值（查看／修改）」，F10 也可以開關。
  - 顯示對象是正在交談的女主，或在名單裡點選的女主。
  - 內容：關係勾選、心理摘要（含貞操、魅抗、你的魅力、能不能獨處）、25 項數值滑桿（陌生好感上限、好感、興奮、欲望、話題點、可談次數、貞操、11 個情感軸、5 個需求、她眼中你的財力、她的錢包）。
  - 拉滑桿會直接存檔。
- **測試**：
  - 單元測試 `OpenKoikatsu.StreetSocial.Heroine.ChastityAndConfession`。
  - 探針 `OK_STREET_UI_PROBE=chastity`：貞操 5 的陌生人答應獨處，貞操 100 的拒絕。
