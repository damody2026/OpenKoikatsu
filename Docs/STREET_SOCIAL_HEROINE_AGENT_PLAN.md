## 1. 設計原則：開放世界

1. **沒有劇情軌道。** 女主的處境全部來自她的個人設定，例如缺錢、想買東西、家裡有事、要考試。她會自己想辦法：多排班、跟朋友借錢、開口找玩家。玩家可以發現、幫忙、利用，也可以完全不理。Director 不會「派發危機」，只負責讓玩家有機會聽說（§14）。
2. **規則不寫死門檻。** 不會出現「好感 80 才能做 X」這種規則。是否答應由人格、關係、心情、場合、她的經濟狀況綜合決定：結果一律由規則分數和擲骰決定；LLM（DeepSeek）只在和玩家互動時負責台詞（§6.0）。
3. **互動盡量不限場所。** 大部分互動在哪裡都能做，只是在不合適的場合會很奇怪。旁人會看、她會尷尬、店員會出聲制止、事情會變成謠言（§9）。只有少數硬限制，例如男生不能上女生宿舍樓上、打烊後不能進店。
4. **錢是真的。** 每一筆消費都會從某人的錢包扣掉。女主的錢包有收入、固定支出和存錢目標，請客會影響彼此的人情帳。
5. **LLM 不直接改數值。** LLM 只輸出 Intent JSON，由 UE Validator 檢查後提交。

## 3. 架構：Rust 執行在同一個 process 內

```
OpenKoikatsu.exe
 ├─ UE game thread（OKStreetSocialScene）
 │    ├─ 世界權威：位置、時鐘、Rel 數值、錢包餘額、Commit
 │    ├─ 規則 Validator（數值上限、intent 白名單、金額、場合合適度）
 │    ├─ 日程執行、需求衰減、點餐與結帳流程（規則，不叫 LLM）
 │    └─ 每 tick：okm_poll() → 驗證 → 提交
 │
 └─ ok_mind.dll（Rust cdylib，FPlatformProcess::GetDllHandle 動態載入）
      ├─ 自己的 worker threads，不碰 UE 物件
      ├─ 記憶、檢索、反思、每日計畫、相遇、謠言、Director 評分
      ├─ LLM 佇列（ureq + rustls → DeepSeek）：優先序、速率、預算
      ├─ 女主檔產生、catalog 讀取、點餐偏好判斷、帳本歷史、未來表
      └─ 存檔：Saved/StreetSocial/mind/*.json（原子寫入）＋ trace.jsonl
```

**C ABI**（`Tools/ok-mind/include/ok_mind.h`）：

| 函式 | 用途 |
|---|---|
| `okm_open(config_json)` | 開啟 |
| `okm_submit(json) -> id` | 提交非同步工作 |
| `okm_query(json) -> json` | 同步讀取 |
| `okm_poll() -> json[]` | 取回已完成結果 |
| `okm_free` | 釋放回傳字串 |
| `okm_save` | 存檔 |
| `okm_close` | 關閉 |

**實作規則：**

- 每個入口都包 `catch_unwind`，並設定 `panic = "unwind"`。
- 用 DLL 而不是 static lib：避免 CRT 和 allocator 衝突，不必改 `Build.cs` 的連結設定，改 Rust 也不必重編 UE。
- DLL 不存在時退回目前的行為。
- 打包：`prepare_interaction_runtime_host.lua` 和 `stage_street_social.lua` 要把 DLL 帶進去，不能動 junction。

## 4. 資料模型

### 4.1 女主檔 `HeroineProfile`（`Saved/StreetSocial/mind/heroines.json`）

**產生方式：** 第一次啟動時，每人呼叫一次 LLM 產生，輸入是卡片的名字、性格、興趣和 persona。之後玩家可以手改，也可以按「重新產生」。

```
id  display_name  age_in_setting(>=18 硬檢查)  archetype(S/H/G/D/E/Q/C)
personality_core{口癖, 自尊, 恐懼, 慾望}  orientation  material  drama_mode_override?
shyness 0–100            // 害羞度：場合合適度的反應強度
public_boldness 0–100    // 在公開場合做親密互動的接受度
occupation{primary, role: staff|manager|owner, workplace_place_id, job_id?, schedule_mask, pay, competence, pride}
home_place_id  favorite_places[]  birthday(2010 曆)  voice_hint
initial_bonds[]  initial_memories[]

money {
  cash, bank,
  income[{source: allowance|parttime|salary|scholarship|family|other, amount, cycle: monthly|weekly|per_shift, payday}],
  fixed_costs[{name: 房租|手機|學費|還款|寄錢回家…, amount, due_day}],
  spending_style: frugal|normal|generous|lavish,
  treat_pride 0–100,          // 堅持自己付或回請的程度（H 型高）
  expects_treat 0–100,        // 期待別人請客的程度（G 型高）
  reciprocity 0–100,          // 有恩必報的程度（E 型高）
  saving_goals[{item, amount, deadline?, why}],
  money_needs[{reason, amount, deadline, severity 0–1, secret: bool, known_by[]}],
  debts[{to, amount, due}]
}

tastes {
  likes[] (catalog item id 或 tag)  dislikes[]  allergies[]  diet: none|dieting|vegetarian|…
  drink{sweetness: 全糖|少糖|半糖|微糖|無糖, ice: 正常|少冰|微冰|去冰|溫|熱, toppings[]}
  spice 0–3  alcohol: never|social|likes  gift_style: practical|cute|luxury|handmade|experience
}
```

**範例：「很需要錢」寫在設定裡**

- 小美的 `income` 是家裡每月零用錢 6,000，加上飲料店打工，每週約 3,000。
- `fixed_costs` 有手機 599。
- `money_needs` 有一筆「媽媽住院費 30,000，期限 2010-10-20，severity 0.9，secret = true」。

她的每日計畫會多排班、少花錢、只點最便宜的東西；心情偏低；可能跟好友借錢。玩家可以從這些地方發現：

- 謠言（好友知道這件事）
- 她的行為（一直在打工、婉拒邀約）
- 她主動開口（必須信任夠高）

**Validator 檢查：**

- place 和 item id 必須存在。
- 所有金額都是非負整數。
- 年齡 ≥ 18。
- 5 人當中至少 1 人有 `money_needs`，至少 1 人是富裕型，至少有 1 組 rival Bond。這條是給 LLM 的多樣性要求，不是硬限制；不滿足時只重試一次。

### 4.2 關係軸（UE，存檔 schema 2）

- 保留舊的 `Favor/Lewdness/Stage`。
- 新增 11 軸，範圍 0–100：`trust, admiration, attraction, affection, dependency, mystique, jealousy, greed, lifestyle_desire, respect, resentment`。
- 新增 `admiration_stage 0–5`。
- 新增人情帳 `treat_balance`：正數表示玩家請她比較多。另有 `last_treat_by`。
- 衰減規則和第 2 版相同。
- **崇拜值和忌妒值是兩個「主屬性」**，在關係面板顯示，並且會扭曲行為（§10）：
  - **崇拜值** `admiration`（0–100）：她對玩家的崇拜。
  - **忌妒值** `jealousy`：分成兩種。
    - 對玩家的整體忌妒，0–100，存在 `FOKStreetRelation`。
    - 對每位其他女主的忌妒，0–100，存在 `Bond.jealousy_a_to_b`。

  兩者都會隨事件變動，並依特質回歸基線。

### 4.2a 特質 `Traits`（寫在 `heroines.json`，由 LLM 產生，可手改，平時不變）

特質是天生傾向，決定狀態值「漲多快、退多快、扭曲多強」：

| 特質 | 0–100 | 作用 |
|---|---|---|
| `worship_proneness` 崇拜體質 | 高：容易崇拜人，崇拜值漲得快、退得慢 | admiration 增益倍率、回歸速度 |
| `jealousy_proneness` 忌妒體質 | 高：容易吃醋，看到小事就起疑 | jealousy 增益倍率、回歸速度、§10 的感知偏差 |
| `possessiveness` 佔有慾 | 高：要你只看她 | 忌妒轉成「行動」的門檻（跟蹤、查勤、搶人） |
| `insecurity` 不安全感 | 高：覺得自己會被拋棄 | 被冷落時忌妒和依賴一起上升 |
| `competitiveness` 好勝 | 高：會跟其他女主比較 | 對女主的忌妒轉成「比拚」（請客、送禮、打扮） |
| `self_esteem` 自尊 | 低：崇拜容易變成卑微 | 崇拜高時的順從程度 |
| `tsundere` 傲嬌 | 高：表面的言行和真實屬性相反 | §10.4 的表裡機制強度 |
| `mask_axes[]` | 傲嬌作用在哪些屬性上，預設 `affection`、`admiration`、`jealousy` | 只有這些屬性會被反轉表現 |

### 4.2b 魅力與抗性（詳細規則見 §12）

| 屬性 | 誰有 | 範圍 | 來源 |
|---|---|---|---|
| `appearance_charm` 外表魅力 | 男主 | 0–100 | 基礎值（**在設定裡手動填，預設 50**）＋服裝等級（百貨 3F 衣服、手錶）＋整潔（剛泡完溫泉、剛打完球）＋穿著是否符合場合 |
| `wealth_charm` 金錢魅力 | 男主 | 0–100 | **每位女主各自認知**：她看到或聽說的消費、請客、禮物價格、身價謠言（`player_wealth_band`）、隨身配件。不是你真正有多少錢，而是她以為你有多少。 |
| `charm_resistance` 魅力抗性 | 女主 | 0–100 | 寫在 `heroines.json`（LLM 產生，可手改）。見過世面、自尊高、重視內在的人比較高。 |
| `money_resistance` 金錢抗性 | 女主 | 0–100 | 寫在 `heroines.json`。G 型低，`material: Romantic` 高。`money_stress` 會暫時降低它。 |

四個值在 UI 上都顯示精確數字。男主的金錢魅力會顯示面板上目前選取的那位女主所認知的值。

### 4.3 需求 `Needs`（UE，只有女主有；玩家沒有需求）

| 需求 | 衰減 | 補充方式 | 太低時 |
|---|---|---|---|
| satiety 飽足 | 約 6 遊戲小時從 100 降到 30 | 吃東西（catalog `effects`） | 計畫插入用餐；心情下降；會說「好餓」 |
| energy 精神 | 白天緩降，打工和運動扣得快 | 睡覺、咖啡、休息 | 想回家；拒絕長時間活動 |
| fun 樂趣 | 緩降 | 逛街、遊戲、寵物、溫泉… | 主動邀人出去 |
| social 社交 | 一個人時緩降 | 和任何人聊天、相處 | 傳訊息、去人多的地方 |
| hygiene 清潔 | 運動、潑水會大扣 | 宿舍洗澡、溫泉 | 婉拒近距離互動 |
| money_stress 經濟壓力 | 由錢包計算：餘額 ÷ 7 日預估支出，加上 money_needs | 收入、借款、別人幫忙 | 少花錢、多排班、心情低落、可能開口借錢 |

需求會傳給每日計畫和即時改計畫的規則層，也會進入 prompt 的「她現在的狀態」。

### 4.5 記憶 `MemoryRecord`（Rust）

```
id, owner, t(遊戲時間), type(observation|conversation|event|reflection|gossip|plan|summary|prediction)
kind(見下)  summary(第一人稱 ≤80 字)  entities[](player, heroine ids, place id)  place_id
importance 0–1  emotional_tag  quoteable(bool)  source(self|player|heard_from:<id>)
confidence 0–1(謠言 <1)  related_ids[]  pleasure_ids[]  door(fast|mid|slow)  last_recalled
author(llm|template)   // 這條記憶的文字由 LLM 寫成，還是由規則範本產生（§6.0）
claim?                 // 預言用（§15）
```

`kind` 的種類：

- 原有：`prediction`、`money_help`、`entrust`、`gift`、`date`、`insult`、`betrayal`、`reveal`、`confession`、`birthday`、`outing`、`touch`、`rescue`。
- 新增：
  - `treat`：誰請誰、吃了什麼、多少錢
  - `remembered_taste`：玩家記得她的喜好
  - `awkward_scene`：在不合適的場合做了什麼、誰看到
  - `loan`、`repay`、`shared_shift`（一起打工）、`umbrella`、`sick_visit`、`sleep_together`、`intimacy` 等

**重要性：**

- 依事件種類給基準值。例如告白 0.9、普通聊天 0.3；預言當下 0.5，命中後 0.9，幫她翻身 1.0。
- 只有和玩家的對話摘要才由 LLM 打分。

**檢索分數：** 正規化(標籤和實體重疊 + 關鍵字) + 正規化(重要性) + 正規化(`0.99^遊戲小時`)，再加上 §10 的扭曲偏好。

**額外觸發：** 周年、生日、同一實體。

## 5. 時間模型

- **曆法與速度：** 2010 年日曆，從 2010-09-01（開學）開始。1 遊戲日 = 1 小時現實時間，凌晨 04:00 換日。
- **睡覺：** 沿用現有的 `StartSleep` 和 `sleep_*` activity，跳到 07:00。另外新增「等待到下個時段」。
- **跳過的時間：** 由 Rust 做摘要模擬。需求按時間扣減、自動補餐，自己吃飯的錢從她的錢包扣；女主相遇用規則決定；薪水、零用錢、預言、托付照常結算。
- **不能跳過的情況：** 有高優先事件尚未處理時。
- **營業時間與門禁：** 依 catalog 的 `open`。女生宿舍門禁 23:00 會成為「送她回宿舍」的自然時機。

## 6. 行為迴圈

### 6.0 LLM 使用原則：只有和玩家互動時才呼叫 DeepSeek

**不使用 Jev，也不使用本地決策模型。** LLM 只有 DeepSeek，而且只在「和玩家互動」時才呼叫。其他所有行為都用規則和行為樹。

**什麼算「和玩家互動」**——以下任一情況成立，這位女主就處於互動中：

- 正在 FreeTalk，無論是她先開口還是玩家先開口
- 同行，包含三種模式（§13.2）
- 在一起做 activity：Pair、Facility、Photo、Restroom、Read
- 一起睡（§12.5）或進行親密動作（§12.4）
- 和玩家通電話或傳訊息
- 在玩家旁邊演出的女主相遇，也就是被旁聽（§6.4）
- 結帳、點餐、送禮、借錢等待決事項（§7.1）的雙方之一

**每次 DeepSeek 呼叫的用途：**

| 用途 | 時機 | 次數 |
|---|---|---|
| 對話台詞與 Intent | 互動中每一輪 | 依玩家而定 |
| 女主主動開口的第一句 | 自主接近（§13.1）走到玩家面前、打電話接通時 | 每次 1 |
| 旁聽演出 | 女主相遇且玩家在旁邊 | 每次 1 |
| 互動結束的摘要記憶 | 一段互動結束時 | 每段 1 |
| 當天有互動的女主反思 | 換日時，只限當天和玩家有互動的女主 | 每人每天 ≤ 1 |
| 女主檔產生 | 第一次啟動，或按「重新產生」 | 每人 1（一次性） |

**完全不呼叫 LLM 的部分：**

- 每日計畫
- 日程執行
- 自主消費
- 需求
- 不在玩家旁邊的女主相遇
- 謠言傳播
- 自主接近的判斷
- 邀請接受度的擲骰
- 扭曲（§10）
- 當天沒有互動的女主的每日摘要

這些記憶的文字由範本產生（`author: template`），例如「{時段}在{place}吃了{item}，花了{price}元」「聽{source}說{fact}」。

**DeepSeek 失敗或超出預算時：** 互動中的台詞改用範本台詞庫（依 intent 和 emotion 分類），數值照規則照常結算，遊戲不會卡住。

### 6.1 每日計畫：規則產生

每天 04:00 換日時，每位女主跑一次規則產生器，不使用 LLM：

1. **硬佔用：** 依職業的 `schedule_mask` 填入上課和上班時段，週末和學期考試週有不同的範本。
2. **約定：** 把和玩家的約定（`plan` 記憶）放進對應的時段。
3. **需求和目標：** 依需求和錢包填入：
   - 三餐時段排 `meal`，地點依 tastes、預算、喜歡的地點加權抽選。
   - `money_stress` 高時：多排打工班（catalog `jobs`），減少 leisure 和預算。
   - 有 `saving_goals`：排 errand 去對應的店，到時才決定買不買。
   - `social` 需求：和 Bond heat 高的女主約同一個時段、同一個地點（`with`）。
   - 忌妒 ≥ 61（§10.2）：在玩家常去的地點、或情敵的日程地點排一個「剛好遇到」的區塊。
4. **空檔：** 剩下的時段用 utility 分數從 favorite_places、季節、天氣挑 leisure，或排 rest。
5. **Validator：** 檢查營業時間、門禁、預算是否超過可用現金；不合就改排 rest 或回 home。

輸出的 DayPlan 每個區塊都標 `source`，Inspector 可以看到每個區塊是怎麼排出來的。

### 6.2 日程執行：行為樹

每位女主每 tick 跑一次行為樹（BT），由 UE 執行。樹的結構固定，節點參數讀自 profile、屬性和 `BehaviorBias`：

```
Root (Selector)
├─ [互動中] → 交給互動系統（FreeTalk、同行、activity），BT 暫停
├─ [硬限制] 門禁、打烊 → 回 home 或離開 place
├─ [緊急需求] Selector
│   ├─ satiety < 20 → 找最近、營業中、付得起的餐飲 → 自主消費
│   ├─ energy < 15 → 回 home 休息，或就近坐下
│   └─ hygiene < 15 → 回 home 洗澡，或去溫泉
├─ [主動行為] 有排程的主動行為（§6.6、§13.1）→ 執行
├─ [計畫區塊] Sequence
│   ├─ 不在目標 place → PlaceRoute 移動（不可見時只推進抽象位置）
│   ├─ 在 anchor 上做 activity（工作、上課、用餐、休閒）
│   └─ 區塊到期 → 下一個區塊
└─ [閒置] Utility 選擇：閒晃、看手機、ambient 動作（現有 phone、drink、selfie、groom）
```

**臨時改計畫（規則）：**

- 下雨 → 不去戶外。
- 打烊 → 換到同類的地點。
- 被玩家拒絕 → 心情下降，接著回 home 或去找好友（Bond heat 最高的人）。

**自主消費：** 到了餐飲地點，依 tastes、預算、needs 打分，從 catalog 選品項；付款，播放 prop 對應的動作，更新需求，寫一條範本記憶。

### 6.3 可見與不可見

- **可見：** 在玩家視野內，或和玩家在同一個 place 的女主，實體走 CrowdRuntime，並完整執行 BT。
- **不可見：** 只推進抽象位置（place id 加上預計到達時間）。BT 照常跑，只是動作改成直接結算：一樣會消費、扣需求、寫記憶，只是不生成角色。
- **轉成可見：** 玩家走進她所在的 place 時，在她的 anchor 上生成她。
- **睡覺加速時：** 全部女主都走不可見路徑，以時段為單位批次結算。

### 6.4 女主相遇

**偵測：** 兩人在同一個 place 同時段，或在街上距離 < 4 m，而且雙方都不在冷卻中。

**玩家不在旁邊**（不呼叫 LLM）：

- 由規則決定這次相遇會怎樣：打招呼、一起吃飯、聊天、冷淡擦身而過、爭執。依據是 Bond 的 heat 和 jealousy、修羅場模式、兩人的心情。
- 結算：
  - `bond_delta`
  - 謠言交換：依信任和熱度挑選她知道的 PublicMemory 事實傳給對方；忌妒高時 confidence 會被扭曲
  - 人情帳：一起吃飯時誰請客
- 雙方各寫一條範本記憶，例如「在學生餐廳遇到 B，她說他昨天和 A 去溫泉」。
- 謠言也可能來自這裡，例如「她最近都不跟我們吃飯」。

**玩家在旁邊（20 m 內，或在同一個 place）：**

- 呼叫 DeepSeek 一次，產生 2–6 句對話，雙方都用 TTS 和氣泡演出。
- 玩家可以插話，插話就轉成多人 FreeTalk。
- 結束後寫 LLM 摘要記憶。

**限制：** 同一對每遊戲日最多一次，全域每遊戲小時也有上限。

### 6.5 反思與摘要

- **當天和玩家有互動的女主：** 換日時呼叫 DeepSeek 一次，產出：
  1. 今日摘要
  2. 3 條反思（附證據 id）
  3. 長期 Rel 調整的提案，經 Validator 提交
  4. 對明天的「意圖」，例如「想問他上次的事」「這週要多排班」

  第 4 項會轉成規則可以讀的旗標，餵給 §6.1 的計畫產生器。
- **當天沒有互動的女主：** 不呼叫 LLM。規則產生摘要：當天記憶的範本串接，再加上數值變化。另外檢查經濟狀況，例如餘額 ÷ 7 日支出低於門檻時，寫一條「這個月快撐不下去了」的範本反思，讓隔天的計畫多排班。
- 摘要會取代 `free-talk-memory.json` 截斷就遺失的做法。

### 6.6 主動行為

規則層在每個時段為每位女主計算 `initiative`，超過門檻就排入一個行為。台詞只在真正和玩家接觸時（走到面前或電話接通）才叫 DeepSeek。

| 行為 | 呈現 | 觸發 |
|---|---|---|
| 打電話、傳訊 | NPC phone、contacts | 想見面、問約定、吃醋、托付到期 |
| 街上主動搭話 | 由她發起 FreeTalk | affection 或 appeal 高，而且剛好碰到 |
| 邀約 | invitations ledger | 計畫裡有空檔 |
| 質問、吃醋 | 她先開口 | 聽到謠言，jealousy 跨門檻 |
| 求帶投、求預言 | 她先開口 | admiration_stage ≥ 3 |
| 約吃飯 | – | satiety 低，而且想見玩家 |
| 開口借錢 | – | money_stress 高、trust 高、`treat_pride` 低 |
| 回請 | – | `treat_balance` 偏正，而且 reciprocity 高 |
| 下雨送傘、借傘 | – | 下雨，玩家在附近沒帶傘 |
| 生病求助 | – | 隨機或過勞進入「感冒」狀態 |
| 送禮、等在門口 | 走到玩家常去的地點 | 生日、紀念日；gift_style 是 handmade 且 affection 高 |
| 介紹朋友 | 帶另一位女主過來 | Recruiter 型，affection 高 |

### 6.7 修羅場 A/B/C

三種模式都做，全域預設 B。每位女主可以用 `drama_mode_override` 覆寫，也會依 `orientation` 自動偏移（例如 Poly 在 C 世界中表現得像 B）。

| 模式 | 謠言 | 吃醋 | 撞見事件 | 結果 |
|---|---|---|---|---|
| A | 關閉 | 只對被冷落有反應 | 無 | 冷落、失約會扣分 |
| B | 開啟 | 爭寵、搶約會 | 有，會質問 | 很少分手 |
| C | 開啟，會失真 | 撞見、質問、隱瞞 | 有，會談判 | 導向新規則，例如輪流、公開 |

- 修羅場之後一定寫記憶，避免同一場架一再重演。
- 玩家把錢花在別人身上（請客、送禮），其他女主知道後也會依模式反應。例如 C 模式下，「他請 A 吃 10F 景觀餐廳，卻只請我喝飲料」會成為質問的內容。

## 7. FreeTalk 改造

LLM 呼叫移到 Rust 佇列，模型照舊是 DeepSeek（`deepseek-chat`）。UE 原本的 `PostFreeTalk` 保留，當作 DLL 不在時的 fallback。

**prompt 結構：** 每位女主各自一份持續的 context，依序是 system、壓縮摘要、聊天紀錄、本輪完整狀態，只往後加，超過 100,000 字才壓縮。詳見 §7.0。

**佇列：**

- **優先序：** 互動對話 > 主動開口第一句 > 旁聽演出 > 互動摘要 > 有互動女主的反思 > 女主檔產生。
- **限制：** 同時最多 2 個請求；每分鐘有上限；每遊戲日有預算。
- **重試：** 退避 1s、10s、20s；遇到 429 時暫停低優先的工作。
- **trace：** 每次呼叫寫入 `mind/trace.jsonl`，可以重播。

**估算：** 背景沒有任何 LLM 呼叫，所以呼叫量幾乎都跟著玩家的互動量走。另外每天約 0–5 次反思（只算有互動的女主），加上每段互動 1 次摘要。

**動態尾巴新增：**

- **[場景]：** 每一輪都放，格式固定，和 [時間] 並列。

  ```
  [時間] 2010-09-14（二）19:42 晚上  天氣：小雨
  [場景] 大學城百貨 9F 美食街（室內、公共 P0、熱鬧、可飲食、有店員）；附近約 12 人；
         你們坐在靠窗的桌子；她剛吃完日式咖哩飯；認識的人：A 在同一層（約 15 m）
  ```

  - **資料來源：** place（名稱、About、樓層、room 或 anchor）、§9 的場合描述、CrowdRuntime 的附近人數，以及現有的 `FreeTalkDoing` 和 `FreeTalkNearby`。
  - **換場景時：** 只有這一行會跟著改，system prompt 不變，前綴快取不受影響。

- 她的需求摘要，例如「有點餓」「很累」「最近手頭很緊」。只寫她願意表現出來的；`secret` 的需求要看 trust 才會透露。
- 錢包粗略區間，只有她自己知道。
- 這個 place 的菜單摘要（catalog 動態截取）和場合合適度描述（§9）。
- 人情帳摘要，例如「上次是他請的」。

**輸出 schema 新增：**

```json
"order": {"for":"self|player", "items":[{"id":"dk_pearl_milk","size":"L","sweetness":"半糖","ice":"去冰"}]}?,
"pay": {"who":"me|player|split|ask_player", "insist":0.0-1.0}?,
"money": {"op":"ask_loan|repay|refuse_gift|accept_gift|return_gift", "amount":0}?
```

- **Validator：** 品項必須在這個 place 的菜單上；營業中；付款人餘額足夠，不夠就改成另一個人付或 AA，並在台詞裡反映出來。

### 7.0 快取命中策略（DeepSeek 前綴快取）

**DeepSeek 前綴快取的規則：**

- 預設開啟，只比對請求開頭和之前某次請求**逐字相同**的部分（以 64 token 為單位）。
- 命中的部分大約是原價的 1/10，速度也比較快。
- 第一個不同的字之後，全部都不命中。

**目標：** 每位女主的每次請求，都是她上一次請求原封不動再往後加。

**原則：每位女主各自擁有一份 context。**

- 不同女主本來就該有不同的 context，所以不追求跨女主共用快取。
- 每位女主有一份持續存在的 context，存檔位置：`mind/context/<stable id>.json`。
- 這份 context 存的就是實際送給 DeepSeek 的 messages 陣列，一字不差。

**現況的問題**（`OKStreetSocialFreeTalk.cpp`、`OKStreetSocialScene.cpp:850`）：

1. 超過 10,000 字時，`OKStreetFreeTalkTrimMemory` 會一次從頭砍到剩 7,000 字。每砍一次，system 以後的內容全部不命中。
2. 送出的 user message 有完整的狀態，但歷史只存玩家原話。所以上一輪那則訊息永遠不會命中。

**一位女主的 context 結構：**

| 段 | 內容 | 什麼時候變 |
|---|---|---|
| system | 規則、輸出 schema、intent 白名單、場合規則、地點與活動目錄、菜單目錄、她的 persona、`personality_core`、特質、tastes、職業、住處 | 只有改版或修改她的設定時才變（內容雜湊改變 → 一次全部不命中） |
| 壓縮摘要 | 上一次壓縮產生的長期記憶摘要（第一次壓縮之前沒有這一段） | 只在壓縮時變 |
| 聊天紀錄 | user／assistant 往返，以及系統插入的 `[記憶更新]` 訊息。**只增不改。** | 每輪往後加 |
| 本輪 user message | **完整狀態**，加上玩家說的話或任務指令 | 每輪；送出後原樣併入聊天紀錄 |

**規則：**

1. **每輪都送完整狀態，也原樣存回去。**
   - 每一則 user message 都包含完整的狀態區塊，順序固定：[時間][場景][心情][關係與數值][崇拜][忌妒][內在傾向][需求摘要][錢包區間][人情帳][記憶 top-5][聽說][約定][她對你的認知][待決事項][玩家說]。
   - 送出後，整則訊息原封不動附加到聊天紀錄；assistant 也存原始回傳的內容。
   - 這樣模型每一輪看到的都是同步過的完整狀態，下一次請求的開頭也就是上一次的完整輸入。

2. **超過 100,000 字才壓縮，平常完全不剪。**
   - 每次送出前計算聊天紀錄的總字數。超過 100,000 字就做一次上下文壓縮：
     1. 從最後往前取大約 30,000 字的聊天紀錄，切點要落在一組完整的往返上，並從 user 訊息開始。
     2. 更早的部分交給 DeepSeek 壓縮成摘要。壓縮請求本身也用她自己的 context，任務指令放在最後，所以這次請求大部分會命中。
     3. 摘要必須保留：重要事件、約定、她對你的感受變化、可以引用的原話與記憶 id、和其他女主的關係。
     4. 新的 context = system + 新的壓縮摘要（合併舊摘要）+ 最後 30,000 字的聊天紀錄。
   - 壓縮後的第一次請求會有一次不命中，之後又是只往後加。
   - 壓縮是**唯一**會改動前面內容的時機。換日、閒置、換場景都不會開新會話。

3. **新的記憶用附加的方式送進去。**
   - 每日摘要、反思、旁聽演出、其他女主那邊聽來的謠言、範本記憶等，只要和這位女主有關，就在她下一輪互動前附加一則固定格式的 user 訊息 `[記憶更新]…`，以及固定的 assistant「（記住了）」。
   - 不重寫前面的摘要。

4. **其他用途當成分支，不寫回去。**
   - 互動摘要、晚間反思、主動開口的第一句，都是「她目前的完整 context + 最後一則任務指令」。這樣會命中她對話時建好的快取。
   - 任務指令和結果**不寫回** context，只有產出的記憶依規則 3 以 `[記憶更新]` 附加回去。
   - 所以她下一輪對話的開頭仍然是上一輪對話的完整輸入，照樣命中。

5. **兩位女主一起出現的呼叫**（旁聽演出、三人同睡的 FreeTalk）：
   - 每位女主的台詞都在她自己的 context 裡生成。另一位的資料和剛才說的話放在本輪 user message 的完整狀態裡（[同場]區塊）。
   - 演出結束後，整段對話用 `[記憶更新]` 附加到兩位女主的 context。

6. **序列化要穩定：**
   - JSON key 順序、列表排序、數字格式都固定。
   - context 開頭不放時間戳、亂數、request id。
   - system 文字產生一次就快取成字串。
   - 換行和空白一律統一。
   - model 和 `response_format: json_object` 固定不變。temperature 和 max_tokens 不影響快取。

7. **模型與 context 上限：**
   - 根據公開資料，`deepseek-chat` 已在 2026-07-24 被列為舊名稱並停用，新名稱是 `deepseek-v4-flash` 和 `deepseek-v4-pro`。V4 的 context 上限是 1M token，cache hit 價格大約是 miss 的 1/50。
   - **決定使用 `deepseek-v4-flash`。** P0 把 FreeTalk 和 ok-mind 的預設 model 改成它；`deepseek.json` 仍然可以覆寫。
   - 100,000 中文字大約是 60–100k token，加上 system 和摘要，仍遠低於 1M。
   - 門檻做成設定值，預設 100,000 字開始壓縮、保留最後 30,000 字。
   - **換 model 就是一次全面不命中**，所以 model 只在設定檔裡改，執行中不切換。

**量測與驗收：**

- 每次回應都讀 `usage.prompt_cache_hit_tokens` 和 `prompt_cache_miss_tokens`，寫進 `trace.jsonl`。Inspector 顯示每位女主的命中率和目前 context 字數。
- **目標：**
  - 同一位女主除了壓縮後的第一次請求以外，命中率 ≥ 90%。未命中的只有本輪 user message。
  - 分支呼叫（摘要、反思）命中率 ≥ 90%。
- **回歸測試：** 自動檢查同一位女主相鄰兩次對話請求，後一次的 messages 必須以前一次的 messages 為前綴；壓縮那一次除外，而且要記錄下來。不符合就失敗，並指出第一個不同的位置。

### 7.1 對話即操作

**原則：** 生活中所有的選擇都可以用聊天（打字或語音）完成。選單只是捷徑，兩條路走的是同一套 intent 和 Validator。

**做法：**

- **待決事項：** UE 維護一個「待決事項」`PendingChoice`，例如結帳、點餐、送禮、借錢、邀約、要不要進包廂、要不要過夜。

  ```
  PendingChoice{id, kind: checkout|order|gift|loan|invite|enter|stay|split_food|…,
                options[], proposer, deadline_s, context{amount, items, place}}
  ```

- **送進 LLM：** 待決事項會放在 prompt 的動態尾巴，例如「待決：結帳 NT$180（2 杯飲料），選項：player_pays / split / she_pays / let_her_decide」。
- **LLM 判讀：** 玩家說「我請你」「各付各的吧」「這次換妳請」「妳決定」，LLM 回 `{"resolve":{"choice_id":"…","option":"player_pays"}}`。
- **她也是一方：** 她可以先開口（「這次我來！」），由她提出 `propose`。玩家用話回應（「不用啦我來」），系統就用「協商」處理：
  - 雙方各有 `insist` 值。
  - 第 1 輪由規則判定：她的 `treat_pride` 和 `insist` 對上玩家的堅持。
  - 最多 2 輪，之後強的一方勝。
  - 結果寫進記憶，例如「他硬要請」或「我搶贏了」。
- **聽不懂時：** 玩家的話無法對應到選項時，她用台詞追問（「所以是你請嗎？」），待決事項維持不變。超過 `deadline_s`（例如結帳 20 秒）就照她的傾向自動決定。
- **選單並存：** 選單隨時可以按。按下後同樣送出 resolve，她也會用台詞回應。
- **點餐：** 「幫我點一杯半糖去冰珍奶，她要跟上次一樣」→ `order`。「跟上次一樣」由 Rust 從 `treat` 和 `remembered_taste` 記憶解析成具體品項。
- **行動類：** 「我們去吃飯吧」「坐下來」「牽手」「回宿舍」「睡覺」「去打工」都對應到 intent：
  - 現有的 `go:<place>` 和 activity 繼續沿用。
  - 新增 `touch:<kind>`、`sleep`、`work:<job>`、`wait_until:<slot>`。
  - 場合合適度（§9）照樣適用：說「親我」不代表一定會發生。
- **沒有她在場時：** 玩家對著手機（LLM 小幫手模式）或系統輸入框說「去打工到下班」也可以，由同一套 parser 處理。

**輸出 schema 再新增：**

```json
"resolve": {"choice_id":"c12", "option":"split"}?,
"propose": {"kind":"checkout", "option":"she_pays", "insist":0.8}?,
"act": {"kind":"touch|go|activity|sleep|work|wait", "arg":"hold_hands"}?
```

## 8. 生活經濟

### 8.1 目錄

全部定義在 `catalog.json`，內容見 [STREET_SOCIAL_LIFE_CATALOG.md](STREET_SOCIAL_LIFE_CATALOG.md)：

- 每個 place 的營業時間、入場費、低消、服務費
- 品項、價格、季節、客製選項、效果、標籤、道具
- 打工職缺

### 8.2 點餐流程（玩家在餐飲 place 時）

1. **開菜單：** 走到 counter 或 table anchor，或對她說「我們點東西吧」，打開菜單面板。面板列出 catalog 品項，季節品和售完品會灰掉。
2. **點自己的：** 玩家選自己的品項。
3. **點她的**，有兩種方式：
   - **「幫她點」：** 玩家替她選。系統用 tastes 打分：
     - 完全命中（品項加甜度、冰塊）：`remembered_taste` 記憶，affection 和 trust 上升。她會說出「你記得我喝半糖去冰」這類台詞。
     - 普通：小幅加分。
     - 踩到 dislikes 或 allergies：她會婉拒或勉強喝；relationship 不扣，但寫一條記憶。
   - **「讓她自己點」：** 依規則選，必要時由 LLM 說出她點了什麼。預算會受經濟壓力影響，壓力高時會點最便宜的，或說「我不餓」。
4. **結帳：** 依 §8.3 決定誰付錢。
5. **用餐：** 用餐動作依 `prop`，沿用現有 Pair 的 meal、drink 動作。用餐時可以觸發 `shareable` 互動：分著吃、餵她吃、間接接吻。這些互動也受 §9 的場合合適度影響。
6. **結束：** 更新需求，寫入記憶和交易。

### 8.3 請客與付款

結帳時玩家可以選：

| 選項 | 效果 |
|---|---|
| 我請 | `treat_balance` 增加。她的反應依性格：`expects_treat` 高的理所當然，`treat_pride` 高的會推辭，D 型會感動。 |
| 各付各的（AA） | 對等，沒有額外效果。Q 型偏好這個選項；初期關係也最自然。 |
| 讓她請 | 只有她願意時才成立。依她的 `treat_pride`、`reciprocity` 和錢包決定，不行時她會說「這次你請嘛」。 |
| 交給她決定 | 規則先算她的傾向，必要時 LLM 用台詞表達，例如「上次你請了，這次換我」。 |

**女主主動搶著付：** `treat_balance` 偏正、reciprocity 高、錢包夠時，她會在結帳前先說要付。玩家可以讓她付，或堅持自己付（她的 respect 和 affection 可能微升，也可能被說「你很固執」）。

**人情帳的長期效果：**

- 長期一直由玩家請：G 型 lifestyle_desire 上升；E 型 dependency 上升；H 型 respect 可能下降（「他是不是把我當成要人養的」）。
- 長期一直 AA：Q 型的 respect 上升。

**請客的社交意義：**

- 只請其中一人，而其他女主看到或聽說時，會依修羅場模式產生反應。
- 在高級 place 請客，例如 10F 景觀餐廳或飯店，會提高 `player_wealth_band` 謠言的熱度。

### 8.4 送禮

- 在任何 place 買下 `giftable` 品項後放進背包，送禮可以在任何地點進行。
- 評分 = 她的 `gift_style` 和 tastes 的匹配度 × 場合 × 時機（生日、紀念日、沒有理由）× 價格和關係是否相稱。
- **太貴而關係太淺：** H 和 Q 型會拒收或覺得有壓力；G 型直接收下；有些人會想回禮。
- **送錯：** 不扣好感，但寫一條記憶。她可能日後把禮物轉送或退回，分手時會「歸還禮物」。
- **她也會送玩家禮物：** 依 gift_style 和預算，寫成主動行為。

### 8.5 借錢與還錢

- **雙向都可以借：** 她向玩家借，或玩家向她借。
- **借據：** 存在 `debts`，到期前她的計畫會優先還錢。
- **沒還錢：** 依 relife 的「托付違約」規則處理：trust 和 affection 下降、resentment 上升，可以補救。
- **玩家不收還款：** 和「全給她」的效果相同。
- **她的 `money_needs` 被玩家解決時：** 寫一條高重要性記憶（kind `rescue`，importance 1.0）。依類型分別提升 dependency 或 trust；E 型會長期想回報。

### 8.6 打工（所有商家都可以打工，女主和男主都可以）

職缺清單、時薪、班別、工作點（stations）、工作動作，全部列在 [CATALOG §3](STREET_SOCIAL_LIFE_CATALOG.md)。

#### 8.6.1 應徵與排班

- **應徵方式：** 在店裡對店長說，或用手機 App。可以用聊天（「我想來這裡打工」→ intent `apply:<job>`），也可以用選單。
- **錄取判定：** 依 competence、外表魅力（服務業加分）、是否為學生（校內工讀限學生）、班別衝突。不會叫 LLM。
- **玩家排班：** 在手機的班表 App 選班，寫進 `PlayerShifts`。
- **女主排班：** 由 §6.1 的計畫產生器排。
  - `occupation.workplace_place_id` 是固定工作。
  - `money_stress` 高時，會加排 catalog 的其他班。
  - 學生不會排到上課時間。
- **女主中途應徵：** 女主也會自己應徵新工作。例如缺錢時，規則層會挑時薪高、班別合得上的職缺；這件事會寫成記憶，也可能變成謠言。
- **同班查詢：** Inspector 和手機班表 App 會顯示同一班的人。玩家可以刻意去排和某位女主同一班。

#### 8.6.2 上班時必須待在工作地點

- **上班中的角色**（`OnShift`）被綁在打工地點：只能在這個 place 的房間範圍內移動，主要待在 `stations`。
- **女主：** 行為樹的「計畫區塊」節點在上班時段只會執行工作，不會離開。
  - 例外只有兩種：緊急需求（生病、極度疲倦），這時規則會讓她請假或早退；以及這個時段結束。
  - 她不會應玩家的邀約離開：「我在上班啦，X 點下班」。邀約會改成約下班時間，並寫成約定。
- **玩家：** 走到門口要離開時，會跳出「要早退嗎？」。
  - 選擇早退：扣這班的薪水、店長評價下降。同班的女主依性格反應，例如「欸你走了我一個人怎麼辦」，或幫你掩護。
  - 沒到班就算曠職：評價大降，累積多次會被開除。
- **工作動作：** 角色依 `tasks` 在各個 station 之間輪流，播放對應的工作動作（收銀、搖飲料、端盤、上架…）。
  - 動作沿用現有的 counter、drink、seated、phone 等 clip，搭配道具。
  - 缺的動作列為資產需求，先用通用的「站在櫃台操作」循環代替。

#### 8.6.3 邊打工邊聊天

玩家上班時有兩種模式，可以隨時切換：

| 模式 | 時間 | 能做什麼 |
|---|---|---|
| **邊做邊聊**（預設，有同班的女主時） | 正常速度（1 遊戲日 = 1 小時） | 玩家角色自動執行工作動作；可以自由和同班女主 FreeTalk，也可以和來店的客人（其他女主）互動 |
| **專心上班**（快轉） | 時間加速（例如 8 倍），直到下班或發生事件 | 不能聊天；同班互動改用規則結算並寫成範本記憶 |

快轉會在發生事件時自動中斷，例如：同班女主主動跟你說話、有認識的女主來當客人、店長叫你、尖峰時段來了。

**聊天時的 [場景]：** 自動帶入打工的狀態，例如：

> [場景] 飲料店（你們都在上班，你在收銀、她在調飲台）；現在是晚餐尖峰，排隊 5 人；店長在後面；離下班還有 1 小時 20 分

**忙碌度：** 由人潮決定 `busy` 0–1（依時段，也參考 CrowdRuntime 的客人數）。

- 尖峰時聊太多：店長出聲，評價下降，她也會說「先忙啦」。
- 離峰時：可以好好聊。
- 這就是打工版的場合合適度（§9）：上班摸魚的程度 = 聊天量 × busy。

**同班互動**（都可以用聊天觸發，或由她主動）：

| 互動 | 說明 |
|---|---|
| 教你做事 | 她資歷較深、competence 高時，會教新人。respect 或 admiration 依結果變化 |
| 互相掩護 | 一方犯錯或偷懶被店長看到時，另一方幫忙說話。trust 上升 |
| 換班、代班 | 她有事時請你幫她代班，或你請她代班。這是人情帳的一種 |
| 員工餐 | 休息時間一起吃，品項來自店裡的菜單，免費或員工價 |
| 一起收店 | 打烊前最後一班，人少、P1，適合聊私事 |
| 下班一起走 | 下班後自動提議一起走（§13.2 並行模式），也是送她回宿舍的好時機 |
| 發薪日 | 一起領薪水，提議去吃一頓 |
| 搶客人、比業績 | 好勝心高的女主會想贏你，或想贏同班的另一位女主 |

這些都寫成 `shared_shift` 記憶。同班次數會累積成 Bond（`coworker`），heat 上升。

#### 8.6.4 女主上班、玩家是客人

- 玩家到她打工的店裡，她會以店員身分接待。點餐流程反過來由她負責：她會記得你的口味，可能偷偷招待、多給料，也可能裝作不認識（傲嬌、或怕被店長看到）。
- 上班時她能聊的時間受 busy 和店長限制。久聊會讓她被念，她會因此有點生氣或害羞。
- 其他女主看到她在上班時和你很親近 → 謠言或忌妒，依修羅場模式決定。

#### 8.6.5 玩家上班、女主是客人

- 女主（依她的計畫）來店裡用餐或購物時，由玩家接待：幫她點單、推薦、算帳。
- 可以請她（用自己的薪水），或偷偷招待（被店長發現會被扣評價）。
- 同班的女主看到你對某位客人特別好 → 忌妒值變化（§10）。

#### 8.6.6 薪資與評價

| 項目 | 規則 |
|---|---|
| 薪資 | 時薪 × 實際在班時數。每班結算，或在每月 payday 統一入帳（依職缺設定）。早退時按比例扣，曠職沒有薪水 |
| 店長評價 | `job_rating` 0–100，受出勤、摸魚、尖峰表現、客人反應影響。高評價會加薪或升職（例如外場升組長）；低評價會被少排班，甚至開除 |
| 女主的工作表現 | 依 competence 和心情，用規則結算，影響她的收入和心情。被開除會寫成高重要性記憶，並提高 money_stress |

#### 8.6.7 店長

**預設：** 店長只出現在對話框和手機訊息裡，不生成角色、不佔 CrowdRuntime。

| 店長的工作 | 呈現方式 |
|---|---|
| 面試 | 對話框，例如「店長：明天下午可以來上班嗎？」，結果由規則決定 |
| 排班、換班、代班 | 手機訊息 |
| 出聲提醒 | 尖峰摸魚或久聊時跳出「店長：先招呼客人喔」 |
| 評價、加薪、開除 | 手機訊息，或下班時的對話框 |

台詞使用範本台詞庫，不呼叫 LLM。

**女主當店長**（`occupation.role = manager`，或 `owner` 表示自己開店）：

- **由誰設定：**
  - 在 `heroines.json` 手動設定。
  - LLM 產生女主檔時也可以提議，但每家店最多一位店長。
  - 創業線（§15）由玩家聘她當店長時，也會設成這個值。
- **人在店裡：** 她依自己的日程在營業時段待在店裡，站在櫃台或巡場。這段時間她算「上班中」，會被綁在店裡（§8.6.2）。
- **店長工作改由她本人執行：**
  - 面試：玩家應徵時直接跟她談，走 FreeTalk。錄取用 §12.2 的公式判斷：appeal、她對你的印象、店裡缺不缺人。
  - 出聲提醒：由她親自來念你，語氣依她的性格和你們的關係。好感高時可能睜一隻眼閉一隻眼，傲嬌的話嘴上更兇。
  - 評價、加薪、升職、開除：數值仍由規則計算，但會受她的屬性扭曲（§10）：崇拜或好感高時評價偏寬鬆；對同班另一位女主忌妒時，可能排班刻意把你們分開。
  - 排班：會依她的偏好調整，例如想和你多相處就多排你們同一班。
- **她是你的上司：**
  - 新增互動：被她指導、被她留下來加班、她請員工吃飯、私下求情、在她面前和其他店員太親近。
  - 會影響忌妒的情況：其他女主在這家店打工時，店長女主可能偏心或刁難；修羅場模式照常作用。
- **她不在店裡時**（休假、下班、生病）：店長工作退回對話框和手機訊息。
- **LLM 使用：** 她是女主，所以和玩家互動時照 §6.0 呼叫 DeepSeek；沒有和玩家互動時，她的店長工作（例如評價其他女主店員）用規則結算。

## 9. 場合合適度

**原則：** 大部分互動在哪裡都能做，只是在某些場合會很奇怪。系統不阻擋，而是產生後果。

### 9.1 場合描述（每個 place，以及 place 內的 room 或 anchor 區域）

```
privacy: P0 公共 | P1 半公共 | P2 可鎖 | P3 私密      (relife SCN)
quiet: 0–1            // 圖書館 1.0，操場 0
formality: 0–1        // 景觀餐廳、飯店大廳高
food_allowed: bool    // 圖書館閱覽區、水族館展區不能飲食
crowd(t): 0–1         // 依時段的人潮：學餐中午最滿
staff: bool           // 有店員或管理員會出聲
```

`crowd` 也會參考 CrowdRuntime 實際在附近的 NPC 數量。

### 9.2 互動的合適度標籤

每個互動都有一組「需求」，例如：

| 互動 | 需求 |
|---|---|
| 吃東西 | food_allowed |
| 大聲聊天、講電話 | quiet 低 |
| 牽手 | privacy ≥ P0，公開大膽度低 |
| 擁抱 | privacy ≥ P1，或 crowd 低 |
| 親吻 | privacy ≥ P1，crowd 低 |
| 餵食、分食 | crowd 低，或關係是 lover |
| 躺下睡覺 | 有床，或 privacy ≥ P2 |
| 換衣服 | P3 |
| 潑水 | 戶外 |
| 喝酒 | 有販售或可外帶，而且不是學校 |

成人互動仍然受 relife 規則限制：在 P0 不生成演出，改成「換個地方」（relife SCN §R）。

### 9.3 計算與後果

`awkwardness = Σ 不符合的程度 × crowd × (1 + formality)`，結果會影響以下幾方：

- **她的反應：** 依 `shyness`、`public_boldness`、關係階段、心情。
  - 低尷尬：她配合，也許有點害羞，臉紅。
  - 中尷尬：她小聲抗議、四處張望，答應但縮短互動時間。
  - 高尷尬：她拒絕，或拉著玩家離開；屢次發生會讓 respect 下降。
  - 大膽型在中尷尬時反而覺得刺激，attraction 上升。
- **旁人：** crowd 高時，附近 NPC 會轉頭看，用現有的 Look 動作。
- **店員或管理員：** staff 為 true 且尷尬超過門檻時出聲，例如圖書館員說「請小聲」、店員說「這裡不能…」。
- **謠言：** 有其他女主在場或在附近時，寫成 public memory，熱度和 awkwardness 成正比。例如「他們在學餐餵來餵去」。
- **記憶：** 寫一條 `awkward_scene` 記憶。這可以變成好回憶（「那次在圖書館偷吃東西被罵」），也可以變成黑歷史。

**送進 LLM：** 動態尾巴會有一行說明現在的場合，例如：

> 場合：圖書館閱覽區（安靜、禁止飲食），周圍約 8 人，你們在吃洋芋片。

台詞由 LLM 依這行說明自然反應，數值則一律由規則決定。

## 10. 屬性扭曲行為（崇拜、忌妒，以及其他屬性）

**原則：** 屬性不只是分數。屬性高到一定程度時，會改變她怎麼感知、怎麼記憶、怎麼決定、怎麼說話。這四個層面都由規則實作，LLM 只負責把結果演出來，所以行為穩定，可以調整，也能重播。

### 10.1 扭曲的四個層面

| 層面 | 實作位置 | 例子 |
|---|---|---|
| **感知**：怎麼解讀發生的事 | Rust 觀察事件寫入記憶前，套用 `BiasFilter` | 忌妒高：「他跟 A 說話」被記成「他又在跟 A 曖昧」，importance 拉高，emotional_tag 是吃醋。崇拜高：「他預言沒中」被記成「他一定有他的理由」，importance 降低。 |
| **記憶與檢索** | 檢索分數加上偏好項 | 忌妒高時，優先想起和情敵有關的記憶；崇拜高時，優先想起他厲害的時刻（quoteable 戰績）。 |
| **決策** | UE 規則層：日程、主動行為、結帳協商、`PendingChoice` 傾向 | 見 §10.2 的表。 |
| **表達** | prompt 動態尾巴的「內在傾向」一行，加上 emotion 偏移 | 「你現在非常崇拜他，對他說的話幾乎照單全收；但你很怕他被 A 搶走」。 |

### 10.2 扭曲表

**崇拜值 `admiration`**

| 區間 | 狀態 | 感知與記憶 | 決策 | 表達 |
|---|---|---|---|---|
| 0–20 | 普通 | – | – | – |
| 21–40 | 欣賞 | 記住他的戰績 | 會問他意見 | 偶爾稱讚 |
| 41–60 | 佩服 | 他的失誤被淡化 | 點餐和行程常說「你決定」；`PendingChoice` 傾向照他的選擇 | 主動說他厲害；求帶投（預言線） |
| 61–80 | 崇拜 | 失誤會被合理化；別人說他壞話時，她會反駁並降低對方的 Bond | 會托付錢；排計畫時會配合他的空檔；推掉其他約 | 用敬語或撒嬌；模仿他的口頭禪 |
| 81–100 | 盲從 | 幾乎不記負面事件 | 他說什麼都答應：Validator 的同意門檻大幅降低，但 §10.5 的硬限制仍然有效 | 把他講成「神」；向其他女主炫耀他（謠言源頭） |

**忌妒值 `jealousy`**（以對玩家的忌妒和對特定女主的忌妒中較高者計算）

| 區間 | 狀態 | 感知與記憶 | 決策 | 表達 |
|---|---|---|---|---|
| 0–20 | 平靜 | – | – | – |
| 21–40 | 在意 | 中性事件有 20% 機率被記成可疑 | 問「你剛剛跟誰在一起」 | 語氣酸 |
| 41–60 | 吃醋 | 謠言的 confidence 自動 +0.2；只記得情敵的缺點 | 搶約會、比拚（請客更大方、送禮）；對情敵的 Bond heat 下降 | 冷淡、鬧彆扭；拒絕他的一部分要求 |
| 61–80 | 強烈 | 把巧合當證據 | 查勤：打電話、傳訊息；日程裡安排去玩家或情敵常去的地方「剛好遇到」；在情敵面前宣示 | 質問；在情敵面前故意親近玩家（受場合合適度約束） |
| 81–100 | 失控 | 選擇性記憶，強化「被背叛」 | 修羅場事件機率大增（依模式 A/B/C）；可能散播情敵的壞話；可能提出「選我還是她」 | 爆發後寫高重要性記憶，冷卻期間 jealousy 回落，但 resentment 上升 |

**組合扭曲**（兩個以上屬性同時成立時，套用組合規則，優先於單一規則）：

| 組合 | 呈現 |
|---|---|
| 崇拜高 + 忌妒高 | 「忠犬型佔有」：極度順從玩家，但對情敵充滿敵意；會想證明自己最有用（送錢、幫忙、包辦）。 |
| 崇拜高 + affection 低 | 「粉絲型」：仰慕但保持距離，不敢主動；被玩家主動接近時反應很大。 |
| 忌妒高 + greed 高 | 用錢比拚：要求同等或更貴的禮物和請客（「你請她吃景觀餐廳，那我呢？」）。 |
| 忌妒高 + self_esteem 低 | 自卑型：不質問，改成自責、退縮、躲著玩家；dependency 上升。 |
| 忌妒高 + competitiveness 高 | 打扮、成績、打工表現都要贏情敵；Director 會給「比拚」場景加權。 |
| 崇拜高 + resentment 高 | 「失望的信徒」：一次重大背叛（托付違約、被撞見）就會讓崇拜急跌，jealousy 轉成 resentment。 |
| dependency 高 + insecurity 高 | 黏人：social 需求衰減加倍；常傳訊息；不想讓他走（門禁前拖時間）。 |
| mystique 高 + admiration 低 | 好奇型：想挖他的秘密，會跟蹤或打聽。 |

**其他屬性的扭曲**（簡表，同一套機制）：

| 屬性 | 扭曲 |
|---|---|
| greed、lifestyle_desire 高 | 點餐挑貴的；`expects_treat` 實際值上升；對奢侈禮物的評分加倍 |
| dependency 高 | `PendingChoice` 傾向「你決定」；拒絕門檻降低 |
| resentment 高 | 舊帳優先被想起；請客被解讀成「想收買我」；協商時不讓步 |
| trust 低 | 不透露 secret 需求；借錢會要求寫下來；預言被當成「運氣」 |
| respect 高 | AA 和她請的比例上升；不想欠人情 |
| 心情低落或疲倦 | 所有扭曲的強度 ×1.3；容易誤解 |

### 10.3 實作

- **計算偏差：** 每個女主每 tick（或每次事件）計算一次 `BehaviorBias`，由 UE 規則層算出，再同步給 Rust。

  ```
  BehaviorBias{
    perception: {suspicion, idealize_player, rival_negativity},     // 0–1
    recall:     {rival_weight, feat_weight, grievance_weight},
    decision:   {defer_to_player, compete, surveil, possessive_display, withdraw, generosity_shift},
    expression: {inner_line: "…", emotion_shift: {...}},
    active_combos: ["devoted_possessive", …]
  }
  ```

- **讀取位置：** 每個扭曲在 §10.2 表格中的「決策」欄就是實際讀取它的規則點：
  - 日程規劃加權
  - 主動行為的 initiative
  - `PendingChoice` 協商
  - Validator 的同意門檻
  - 謠言傳播的 confidence
- **給 LLM 的部分：**
  - `inner_line` 由「區間 × 組合」查表產生，是固定的中文句型，不由 LLM 生成，所以不會亂飄。
  - 只有反思時，LLM 可以提出「她最近變得很黏」這類自我覺察，寫成 reflection 記憶。
- **讓玩家看得到：**
  - 關係面板顯示**精確數字**：崇拜值，以及忌妒值（對你、對每位女主分開列出）。數字旁邊附上扭曲狀態名稱，例如「崇拜 72（崇拜）」「忌妒→A 66（強烈）」。
  - 傲嬌的女主會多顯示一欄「表現值」，例如「好感 78／表現 31 💢」，讓玩家知道她口是心非。
  - Inspector 顯示完整的 BehaviorBias 和特質。

### 10.4 表裡機制（傲嬌）

**原則：** 嘴上和真實相反，行動跟著真實走。這是傲嬌的核心：「才不是為了你呢」，但還是做了。

**表現值：** 對 `mask_axes` 裡的每個屬性計算一個表現值。

```
expressed = true + (inverse - true) × t × situational
inverse   = 100 − true          // 只對「正向」的高值反轉：很喜歡 → 表現得很嫌棄
situational：
  公開場合、有旁人、情敵在場 → 1.0
  只有兩人、P2/P3 隱私           → 0.6
  「破防」條件成立               → 0.0（露出真心）
```

**誰用真實值、誰用表現值：**

| 用途 | 使用 | 例子 |
|---|---|---|
| 記憶、反思、計畫、主動行為的觸發 | 真實值 | 她真的會排時間去你常去的地方 |
| 待決事項的「結果」 | 真實值 | 結帳說「誰要你請啊」，但結果還是讓你請 |
| 台詞、表情、TTS 情緒、肢體反應 | 表現值 | 被摸頭時說「別碰我」，臉卻紅了（表情混合：生氣＋害羞） |
| 謠言傳播 | 表現值 | 其他女主以為她討厭你 |

**破防條件**（任一條件成立，就在那一刻露出真心並寫成高重要性記憶；之後冷卻，再回到傲嬌）：

- 只有兩人，而且她的心情低落或疲倦。
- 你生病，或你受到別人嘲笑時，她出面護你。
- 喝了酒（`alcohol`）。
- 她以為你沒看到或沒聽到時，例如你假裝睡著、旁聽她跟朋友的對話。
- 你指出她口是心非，而且她的真實好感 ≥ 80。
- 你冷落她好幾天之後再見面（忌妒和不安全感會讓面具裂開）。

**和其他扭曲的組合：**

| 組合 | 呈現 |
|---|---|
| 傲嬌 + 崇拜高 | 嘴上說「也就還好吧」，卻偷偷記下你所有的預言，並在別人面前替你辯護 |
| 傲嬌 + 忌妒高 | 嘴上說「你跟誰在一起關我什麼事」，卻馬上傳訊息查勤 |
| 傲嬌 + treat_pride 高 | 搶著付錢時說「我只是不想欠你」 |

**給 LLM 的方式：** 內在傾向那一行同時給真實和表現，例如：

> 你其實很喜歡他（78），但在旁人面前你要表現得很嫌棄（31）；行動上你還是會照真心做，只是嘴硬。

數值仍由規則決定。

### 10.5 硬限制（不受扭曲影響）

- 不能有自傷、暴力、非自願的 intent。忌妒失控只能表現為情緒、言語、社交手段，並經由 relife 的 Validator 過濾。
- 盲從不會繞過成人內容的閘門和場合規則。
- 散播壞話只能是謠言層級（RIV §2），不涉及真實傷害。

## 12. 魅力、抗性、邀請與親密互動

### 12.1 吸引力

每位女主對男主各有一個吸引力值：

```
look_appeal  = appearance_charm − charm_resistance            // −100..100
money_appeal = perceived_wealth_charm(她) − money_resistance   // −100..100
appeal = w_look × look_appeal + w_money × money_appeal
```

**權重 `w_look`、`w_money` 由人格決定：**

- G 型或 `Mercenary`：`w_money` 高。
- `Romantic`：`w_look` 高、`w_money` 低。
- S 型：崇拜值會把兩個權重一起放大。

**扭曲（§10）同樣適用：**

- 崇拜值 ≥ 61 時有加成。
- resentment 高時減半。
- 傲嬌只反轉「表現」，不改變 appeal 本身。

### 12.2 邀請接受度（陌生狀態不一定成功）

所有邀請都用同一個公式，不論是你邀她或她邀你，也不論是吃飯、去某個地方、牽手、過夜，還是親密行為：

```
accept_score = 關係基礎(stage, affection, trust)
             + appeal × 0.5
             + 心情與需求（餓了 → 吃飯邀請加分；累了 → 長時間活動扣分）
             − 計畫衝突（上班、上課大扣；flexible 區塊小扣）
             − 場合尷尬度（§9）
             − 她要負擔的金額 ÷ 她的可用現金
             − 邀請的親密門檻（§12.4 的階梯）
             ± 扭曲（§10）
P(accept) = sigmoid((accept_score − 50) / 10)
```

- **陌生人：** 一般邀請（喝飲料、聊一下）的成功率大約 20–50%，取決於 appeal 和時機。過夜或親密邀請幾乎都會失敗，除非 appeal 極高而且抗性極低。
- **被拒絕：** 寫成記憶。同一種邀請在同一個時段內有冷卻。拒絕的原因由規則決定（「我等等要打工」「我們才剛認識」「這裡人好多」），台詞由 LLM 依原因生成。
- **騷擾：** 被拒絕後立刻再問，累積 3 次以上，會扣 respect、增加 resentment，並可能變成謠言。

## 13. 自主接近與一起行動

### 13.1 自主接近（每 2–10 分鐘判斷一次）

每位女主有自己的計時器，每次間隔隨機取 2–10 分鐘**現實時間**，約等於 0.8–4 遊戲小時。時間到時計算：

```
approach_score = affection 與 stage 的基礎
               + appeal（§12.1）
               + social 需求不足
               + 忌妒（想查勤）、依賴、不安全感
               + 有話要說（未兌現的約定、謠言、借款、她的困境）
               − 計畫衝突（上班或上課中；flexible 區塊扣得少）
               − 和你的距離（不可見、在很遠的 place 會扣分，但不是不可能）
               − 最近被你拒絕的冷卻
               ± 扭曲（§10）；傲嬌會真的過來，但藉口是「剛好路過」
```

結果：

| 結果 | 呈現 |
|---|---|
| 不行動 | 重設計時器 |
| 傳訊息或打電話 | 現有的 NPC phone；可能是約你，也可能只是聊聊 |
| 來找你說話 | 她從所在位置走過來。不可見的女主會在最近的道路或門口生成再走過來。到了之後由她先開口，開始 FreeTalk。 |
| 來找你，並跟著你 | 說完話後自動進入同行，男主為主（§13.2），直到她下一個計畫區塊開始，或你叫她回去 |
| 邀你去某處 | 發出邀請（§12.3）；你答應後進入女主為主模式 |

**限制：**

- **同時接近：** 同一時間最多 1 位女主在走過來的路上。
- **全域間隔：** 任兩次自主接近之間至少間隔 60 秒。
- **你正和別人同行時：** 照常判斷，由修羅場模式決定結果——B 或 C 模式她會走過來，A 或 B 模式她可能轉頭離開並寫成記憶。
- **不打擾的情況：** 你在打工、睡覺、播放私密動作時不會被打擾。唯一例外是 C 模式下忌妒值 ≥ 81（失控）。

### 13.2 一起行動的三種模式

| 模式 | 前後位置 | 玩家能否操作 | 導航 | 什麼時候用 |
|---|---|---|---|---|
| **男主為主** | 男主在前，她跟著 | **可以自由移動**，也可以選目的地自動導航 | 自由移動時用現有的 `StepCompanion` 跟隨；自動導航時用 `StepOuting` | 你約她、你帶路、她接近後跟著你 |
| **女主為主** | 她在前，男主跟著 | **不能自由移動**，只能自動導航 | 新做：她用 `PlaceRoute` 走在前面，男主沿她的 breadcrumb 跟隨（把現有的跟隨反過來） | 她邀你去某處、「跟我來」、她帶路去私密場合 |
| **並行** | 兩人肩並肩 | **不能自由移動**，只能自動導航 | 新做：沿 `PlaceRoute` 走，兩人側向間距約 60 cm、速度相同；遇到門、電梯、窄路時自動改成一前一後，過去後再並排；可以牽手 | 散步、約會途中、你說「一起走吧」 |

**切換方式：**

- **聊天：** 「你帶路」「我帶你去」「一起走吧」「跟我來」，對應 intent `follow_mode: player_lead | her_lead | side_by_side`。也可以用選單。
- **她的偏好：** 強勢、好勝、崇拜值低的女主想帶路；崇拜或依賴高的女主想跟著你；affection 高時偏好並行。她可以提議切換，你可以拒絕。
- **在女主為主或並行模式中按移動鍵：** 會問「要自己走嗎？」，確認後切換成男主為主。如果目的地是她決定的，她會依性格抗議或跟上來。
- **移動中：** 三種模式都可以聊天，[場景] 會隨途經的地點更新。

**實作：**

- 現有功能：`BeginCompanion` / `StepCompanion` 是「她跟著男主」，`BeginOuting` / `StepOuting` 是「男主自動導航，她跟著」。
- 女主為主模式：要新增反向跟隨，讓男主當 follower，並鎖住輸入。
- 並行模式：要新增雙人隊形移動，以及過門、搭電梯時的單列切換。
- 動作沿用 walk locomotion。牽手並行需要新的雙人行走姿勢，列為可選。

### 13.3 約定、任務列表與爽約

#### 13.3.1 約定 `Appointment`

Appointment{id, kind, with(heroine id | shop place id | none), place_id, anchor?,

| kind | 來源 | grace（可以遲到多久） |
|---|---|---|

**取消：** 在 `cancel_deadline` 前取消（預設開始前 2 遊戲小時），用電話、訊息或聊天說「我們改天好嗎」都可以。

- 只有 `date` 會有小幅影響，而且依她的性格不同。

  3. **打分：** 用 relife 的權重，只用來決定上面兩種「推一把」的優先順序。
- **不再使用 `crisis_seed`。** 困境全部來自女主的個人設定，以及世界自然演變（錢包見底、考試不及格）。

#### 交易規則（照真實 A 股，可以在設定關掉部分規則）

| 規則 | 內容 |
|---|---|
| 交易時間 | **每天只有遊戲時間 09:00–13:30 開市**（§15.8），中間不午休；當天不是真實交易日（週末、假日）就休市 |
| 單位 | 買進以 100 股為一手；賣出可以有零股 |
| T+1 | 當天買進的股票，隔天才能賣 |
| 漲跌停 | 主板 ±10%、ST ±5%、創業板（2020-08-24 後）和科創板 ±20%、北交所 ±30%、新股上市首日依當時規則；以資料中的漲跌停價為準 |
| 費用 | 佣金 0.025%（最低 5 元）；印花稅只在賣出時收，2023-08-28 前 0.1%、之後 0.05%；過戶費 |
| 停牌、下市 | 停牌日不能交易；下市的股票依最後價格結算，或歸零（依資料） |
| 除權除息 | 用復權因子處理配股和配息：持股數和現金自動調整，記在帳本 |

#### 成交方式（只有日線資料）

- **盤中走勢：** 由當日的 O、H、L、C 加上種子，用 Brownian bridge 產生一條決定性的分時曲線。只用來顯示，以及決定盤中掛單是否成交；這條曲線一定經過真實的開盤、最高、最低、收盤。
- **市價單：** 以下單那一刻分時曲線上的價格成交。
- **限價單：** 價格落在當日 [L, H] 之間，而且分時曲線在之後的時間碰到這個價位，就成交。
- **流動性上限：** 單檔單日的成交量不能超過當日真實成交量的 1%。這是避免「預知未來」讓財富無限膨脹的自然上限，也會讓大資金必須分散在多檔股票。
- **漲停買不到、跌停賣不掉（§15.8）：** 下單那一刻的價格等於漲停價時，買單一律不成交；等於跌停價時，賣單一律不成交。一字漲停、一字跌停的日子整天都是這樣。

#### 在遊戲中的呈現

- **帳戶：** 遊戲開始時男主**已經開好**陸股帳戶，不需要開戶流程（遊戲化處理，不考慮 2010 年的實際法規）。帳戶一開始是 0 元；在電腦上入金時，新台幣依當日匯率換成人民幣，出金時反向換算。
- **乘風行情（電腦終端，§15.6.1）：** 必須在有電腦的地方操作（§15.6），在電腦前可以用聊天下單（§7.1），例如「幫我買 10 手茅台」；手機只能查看。功能：
  - 自選股、K 線（日、週、月）、分時
  - 下單、委託、持倉、損益、資金明細
- **預言與前世記憶：**
  - 筆記本 App 顯示「前世記得的事」：指數的大方向，以及一份精選的「名股事件」清單，例如某檔股票某年翻了幾倍、某次股災的日期。
  - 不列每一檔每一天的價格。玩家可以查看盤 App 的歷史，但看不到未來。
  - 精選清單由資料自動挑出：年度漲幅前 N 名、指數單日 ±5% 以上的日子。
- **跟女主的互動：**
  - 你對女主預言「這檔下個月會漲停」，走 §15 的預言流程：到期時比對收盤價，結果影響崇拜和 mystique。

  - **女主自己炒股：** 由規則和行為樹決定。G 型和缺錢的女主比較會追高殺低（用真實資料結算），賠錢會讓 money_stress 和心情下降；崇拜階段 ≥ 3 時會來問你明牌。
  - 身價謠言：持倉市值會計入 `player_wealth_band`。在女主面前看盤賺大錢，會提高 money_appeal。
- **存檔：** 帳戶、持倉、委託、交易紀錄都放在 Rust 的 Ledger（§4.7），加上 `kind: stock_buy|stock_sell|dividend|fee`。

### 15.8 開市時間與漲跌停

**開市時間：**

| 市場 | 開市時間（遊戲時間＝台灣時間） | 說明 |
|---|---|---|
| A 股 | 每天 09:00–13:30，中間不休息 | 遊戲用的簡化時段 |
| 美股 | 夏令時間 21:30–隔天 04:00；冬令時間 22:30–隔天 05:00 | 照真實時差：美東 09:30–16:00 |

- **A 股開市時段**約等於現實 11 分 15 秒（1 遊戲日 = 1 小時）；美股約 16 分 15 秒。
- **收市後：** 不能下單，還沒成交的委託自動撤單。
- **交易日：** 依各自的 `calendar.json`，不是交易日就整天休市。A 股和美股各有自己的日曆。
- **美股的日期對應：**
  - 美東 D 日的交易時段，是台灣時間 D 日晚上到 D+1 日清晨。
  - 所以台灣時間 D+1 日 02:00 看到的，是美股 D 日的那一根日線。
  - 美股的週五交易時段，落在台灣的週五晚上到週六清晨。
- **夏令時間：** 由 Rust 依日期計算。美國從 2007 年起，夏令時間是 3 月第二個星期日到 11 月第一個星期日。
- **提早收盤：** 例如感恩節隔天、聖誕夜，美東 13:00 收盤，換算成台灣時間 02:00 或 03:00。資料裡有這些日期的話就照著做；沒有的話先當作正常時段，列為之後補強。

**分時曲線：**

- 當天真實的 O、H、L、C 會套用決定性的分時曲線（§15.2），對應到該市場的開市時段：A 股 09:00–13:30，美股 21:30–04:00 或 22:30–05:00。
- 開市第一刻是開盤價，最後一刻是收盤價，中途一定會碰到真實的最高價和最低價。

**漲停買不到、跌停賣不掉：**

- **A 股：**
  - 只要下單那一刻的曲線價格等於漲停價，買單就不成交。
  - 等於跌停價時，賣單不成交。
  - 已經掛著的買單或賣單，在價格停留於漲停或跌停的期間也不會成交。等價格離開漲跌停，才依一般規則判定。
- **一字漲停或一字跌停：** O = H = L = C，而且等於漲停價或跌停價。整天的曲線都停在漲停或跌停價，所以整天都買不到或賣不掉。
- **分時曲線怎麼產生：** 收盤價等於漲停價，而且當天曾經封板時，曲線會在後段長時間停在漲停價，模擬封板。跌停也一樣。
- **美股：** 真實市場沒有漲跌停，所以 `limit_up` 和 `limit_down` 都是 0，這條規則不作用，美股不設任何漲跌限制。

**介面提示：**

- 漲停、跌停時，按鈕變灰並顯示原因。
- 委託列表把被擋下的單標成「漲停未成交」或「跌停未成交」。
- 女主和你一起看盤時，會對漲停封板、跌停賣不掉有反應。

**幫她翻身、分錢、托付**（relife CAT 類 2）：

- **分錢四選：**

  | 選項 | 效果 |
  |---|---|
  | 全給她 | Trust↑↑ Admiration↑↑ Affection↑ |
  | 抽 20% | 變成商業夥伴 |
  | 五五分 | Dependency↑ |
  | 只拿本金 | Mystique↑↑ |

- **托付：** 她把錢交給你操作，有到期日。
  - 逾期沒還：Trust、Affection 大跌，Resentment 上升，之後可以挽回。
  - 還了本金但沒賺：小跌或持平。
  - 把錢花在其他女主身上：B、C 模式會引爆。

**創業線（只做一條）：**

- 開公司，聘女主當 CEO、秘書或店長。
- `Offer{role, pay, hours, title_public, exclusive}`；她的回應由 LLM 給出（她在互動中）。
- 聘用後她的職業改變，日程跟著改。

**其他設定：**

- 玩家的錢包也遵守 §4.7。初始設定為：
  - 現金：建議 5,000。
  - 每月家裡給的零用錢：建議 8,000，於每月 5 號入帳。
- 女主的財務困境來自 `money_needs`，不是 Director 派發。
- 「全給她」「只拿本金」這類分錢選擇和人情帳、`treat_balance` 共用同一套帳。
- **地點：** 新增彩票店（§15.1）；銀行用便利商店 ATM 或手機網銀（§11.4）。
- **崇拜值的來源：** 預言命中、幫她翻身都會提高崇拜值（admiration）；扭曲效果見 §10。
- **忌妒值和金錢：** 托付的錢被花在其他女主身上時，對那位女主的忌妒值會大幅上升。
