# APNG runtime scene: five-item implementation plan

The acceptance boundary is a native Development room loaded from player APNGs,
not an imported character asset or an isolated shader/pose oracle.

1. Connect background APNG snapshot, reduction, render mesh and private pose
   preparation to the room. Retain private skeletons, accessories, independent
   behavior clocks, player controls and a CPU/GPU toggle.
2. Complete source material family coverage and production source depth/stencil
   rendering, including outlines and near-character shadows. Reject unsupported
   families explicitly; a blank/default material is not a successful result.
3. Capture CPU/GPU at identical camera, animation phase and scene state. Compare
   face, hair, clothes and attached accessories during movement and transitions.
4. Reuse immutable resources across cards and use persistent renderer mesh draw
   commands. Only playback parameters and world transforms should change per frame.
5. Measure 100 selected/random APNGs from selection to all render-ready characters,
   including background preparation and resource upload, with no card-specific Cook
   assets. The cold target is <=60 seconds.

## Implementation decisions

- Share only immutable prepared texture resources, keyed by actual prepared mip
  bytes and explicit sampler/color settings. Material instances remain private.
- Use weak cache ownership so leaving a scene can release unused GPU textures.
- Bound concurrent preparation and GPU commit work; never encode a machine-specific
  affinity/thread configuration as the general solution.
