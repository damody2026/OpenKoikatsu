1. 用正式讀卡入口、KK_384914 與既有實際 GUI 載入量測取得基準，區分 Session 開啟、貼圖準備、引擎物件建立及後處理。
2. 依耗時與相依性改善載入排程。角色參數與共用骨架必須先完成；不允許以錯誤身型先顯示，再造成頭髮或飾品錯位。背景執行只處理來源資料，UObject 與 GPU 資源提交留在遊戲執行緒。
3. 若來源 Session 尚未提供部件流式解碼，先改善已可安全分批的建立階段；不把整體開啟謊稱為部件非同步。
4. 比較同卡載入時間、參數／部件完整性、取消與重載；用四視角確認原 render 未變。
5. 建置並更新正式讀卡入口，記錄實測改善與仍有的限制，錯誤寫入 MD。

## 實測後採用的範圍

- KK_384914 原作卡、實際 Gallery 路徑：首次 GUI 完成 99.021 秒，第二次 8.740 秒；不含引擎啟動與卡片掃描。
- 首次 Session.Open 51.539 秒、貼圖準備 0.418 秒；第二次分別 0.504、0.171 秒。首次原作資源與材質編譯快取建立仍是主要限制。
- 雙人 metadata 查詢原本在遊戲執行緒花費 3.004／2.670 秒。改由 Session 所屬背景執行緒取得，以載入 generation 交付，遊戲執行緒只建立選單。
- 部件提交採每幀軟預算 4 ms、最多 8 個步驟；單件不可中斷，超過預算即讓出下一幀。保持原本 BeginSessionLoad／ContinueSessionLoad 的骨架與部件順序。
- 本輪不修改 KKPreviewActor、材質、光照、UV、輪廓線，也不假裝已支援 Session 內部頭髮／飾品串流。要真正先顯示身體，後續須拆分原作 Session 資源擷取與配件依賴、快取鍵及最後定位提交；僅提前顯示未完成 Actor 並不安全。
- R4 證明 metadata 移到背景後主執行緒 catalog_controls 約 4.6／6.0 ms，但總時間仍為 12.924／14.481 秒，不能宣稱整體加速；背景 metadata 重讀 81 MB bundle 仍花 4.591／7.269 秒。補上共用原作 metadata 快取，依來源檔名、大小、修改／建立時間與目錄清單失效；只保存小型 metadata，不保存角色 Session／動畫時鐘。
- metadata 快取必須通過與直接解析逐欄位等價、solo／pair 隔離、不同來源根目錄、來源新增／替換／刪除／重新加入及多執行緒測試，再重新做正式 GUI 量測。
