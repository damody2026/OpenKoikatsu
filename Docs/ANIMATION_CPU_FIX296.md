# E296：讀卡畫面播放動畫時 CPU 卡頓

## 範圍與計畫

2026-10-05：依使用者最新回報與 `Saved/Logs/CardReader/20261005-201810544-179a7e59.log`，修正讀卡預覽的持續播放成本。採 CPU 顯示模式；不以停掉骨架、衣服物理、表情或降低更新頻率掩蓋卡頓。最後驗收包含乾燥播放、播放中噴射 3 秒／停噴 5 秒、衣服切換、相機與嘴型。

## 已確認原因與通用修改

- `OkSession::skin_all` 使用匯出型 `skin_mesh`／`apply_parent`，每幀重建 OBJ 文字並印出每個網格的診斷。改用同一蒙皮演算法的 `skin_mesh_geometry`／`apply_parent_geometry`。匯出路徑保留原有 OBJ 行為。Rust 測試確認位置、法線和父變換與匯出路徑相等。
- 私有頭髮／附件／衣服骨架各自持有粒子歷史，可獨立求解。一次準備不可變角色碰撞資料，再以 Rayon 執行緒池處理至少八個私有 renderer 的角色；小角色保留串行路徑。未改動求解次序（單 renderer 內）、步長、碰撞、配置或彈簧參數。C001 的 30 個變動姿勢／不同步長測試逐項確認位置、法線、切線與粒子歷史完全等於串行。
- Unreal 每幀上傳未變的附件。比較實際來源位置、法線、切線，僅變動時更新程序網格；角色及附件的 component transform 仍照常更新。大型静態附件可停止重複上傳，不會冻结真正變形的衣服或頭髮。
- 程序網格基礎表面零位移無須逐頂點建立法線旋轉四元數；分離頂點工作採 `ParallelFor`，保留有位移外殼的原運算。
- 非 morph／非眼睛顯示網格可依三角形索引移除未引用的繪製頂點；保留 canonical 來源資料、來源索引映射、所有四組 UV、法線、切線、顏色和繞向。形狀重建後重新映射。此項不能減量本次 C010 的大型附件：其三角形引用了所有頂點，不是本次主要收益。
- 背景六個面在頂點位置未變時保留原網格；位置變動且拓樸相同時更新頂點，不每幀重建 scene proxy。
- Reader 驗收新增五秒真實連續播放、actor CPU 累計、最大值、frame wall-clock 平均值、時間進度、頂點上傳／跳過數及來源到顯示的索引映射檢查。原噴射及換衣驗收繼續執行。工具非同步收集 native stdout/stderr，避免大量診斷輸出污染主工具回應或堵塞 pipe。
