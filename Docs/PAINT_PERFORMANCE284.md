# E284：放開水槍後持續卡頓與 APNG／KKS 讀卡來源

## 根因與實作

使用者 CardReader 日誌 `Saved/Logs/CardReader/20261005-011634878-dabc648d.log` 噴中頭髮、臉、衣服與飾品。先前 E282／E283 的腿部測試只涵蓋 3–4 個表面，不能代表這個情境。新測試改用 March 原卡、預設 2° 散射、頭部目標，連續噴射後再量測放開後八秒，涵蓋 48 個表面、86,992 面；沒有為角色增加面數。

表面遮罩原本跟著每秒 120 次的液滴掃掠重算，每個像素還反覆做世界三角形最近點與重心座標計算。幀時間變長時補算增加，放開後仍持續惡化。原版頭部壓力測試放開後平均整幀 2,142 ms；這是另一個受控重現，不能當作使用者 269 ms 截圖的相同數據。

通用修正：

- 液滴掃掠維持固定 120 Hz；表面輸運與滴落使用独立固定時鐘，預設 20 Hz，沿用 `SurfaceHz`（5–60 Hz）。保留累积時間、有限體積守恆、跨接縫與世界重力方向；表面離散時間較以前粗，並非宣稱逐像素等同 120 Hz。人物覆蓋與附著液滴仍逐顯示幀跟隨目前骨架姿勢。
- 專用三角形圖表直接計算重心座標；內部回溯不查鄰面，接縫保留世界幾何查詢。外部 padding 相同投影點共用計算。
- 遮罩工作只讀前一張快照，各圖塊在工作執行緒獨立計算。先完成所有 map 配置，再取得輸出指標，避免 map 擴充使指標失效。
- 乾燥浮點雜訊小於 1e-12 厚度視為零；低於殘留厚度、沒有可流動油漆的薄層保留足跡與質量。滴落先排除所有像素都不足門檻的圖塊。
- 覆蓋頂點使用持久的頂點編號快取，預算座標轉換與陣列容量；不再每幀建立雜湊頂點表。附著液滴的位置只在顯示幀更新。
- Render Target 只上傳受影響的圖塊行範圍。各個 ping-pong 目標分別記住舊的非零圖塊，更新時連同需要清除的舊區域一起上傳；沒有讀寫同一張貼圖或降低解析度。
- BVH 葉節點逐三角形再做球半徑與容差擴張的包圍盒排除，避開不可能命中的昂貴迭代掃掠；保留最近命中與精確三角形測試。附著面查詢改成集合。

## 讀卡來源與重開

讀卡清單頂部新增「APNG 內嵌資源卡片」／「KKS 遊戲目錄卡片」。APNG 可填入資料夾並按「載入此 APNG 目錄」，空白時預設 `Saved/APNGCards`。兩種來源可以互相切換；記住 APNG 目錄，載入期間禁止改來源。`OK_CARD_DIRECTORY` 只初始化本輪選擇，不能持續蓋掉 UI 操作。

APNG 清單用 PNG chunk header 或同名 okpreview 探測，僅解析可見頁面的卡片資料，不再解讀整個資料夾的全部大卡。APNG 模型使用內嵌或原型包資源，Session 為 portable、遊戲路徑為空。KKS 卡維持原有遊戲目錄與資源解析。

已載入的 portable 模型在同一卡、同服裝、卡檔／外部原型包路徑、大小與修改時間未變時直接重用；更新檔案或換服裝會走完整載入。重開會重設水槍狀態。只保留目前人物，不建立所有卡片的大型記憶體快取。第一次 APNG 載入仍需建立 Unreal 模型、材質與貼圖，不能保證比已有快取的 KKS 卡快。
