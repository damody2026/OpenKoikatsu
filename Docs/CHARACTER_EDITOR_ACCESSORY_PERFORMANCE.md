# 飾品切換與頭髮位置驗收

## 使用者要求

- 正常載入及更換一般飾品後，頭髮維持原卡的綁定與位置。
- 切換瞬間可卡頓，但點選到新飾品完成顯示須不超過 100 ms。
- 完成後至少 60 FPS；保留角色動畫、臉部動作及原本畫質。

## 實作與驗收順序

1. 修正驗收資料：用一般髮夾驗證 parentKey／旋轉／縮放，避免改動假髮；舊錯位輸出不得繼續作為正常驗收來源。
2. 單一 UE 行程量測原始卡、開啟詳細參數及圖片選單的逐幀時間，定位 UI、角色更新、材質及資源載入各自成本。
3. 詳細參數採可擴充的顯示機制，避免數千個離屏控制項持續消耗每幀排版／繪製時間。
4. 飾品採增量更新：保留未變動的身體、臉部、頭髮及衣物；資源準備與可保存資料產生不得迫使每次選取重建七套服裝。
5. 量測實際點選到完成顯示的時間及完成後逐幀時間，另存、讀回、衣物切換及雙手動作回歸檢查；未達門檻的報告保留且不列為通過。

## 後續實作計畫：唯讀骨骼網格重用

先將 UE 骨骼網格建置的完整輸入建立內容指紋：所有參考頂點／法線／切線、索引、UV／頂點色、蒙皮權重、骨架名稱及順序／父子／參考 TRS、全部 morph、描邊選項與遮罩。快取只保存有界弱參照，不持有角色或延長資產生命；共享網格及骨架的 Outer 使用 transient package。角色元件、姿勢、動畫權重及材質 override 仍各自獨立。材質顏色不屬於網格建置輸入，不以此共用材質。

驗收需證明完整相同輸入跨 Session 重用同一網格，UV／權重／骨架／morph／描邊變動不可誤命中，分批載入貼圖及頭髮位置保持一致，再量測真實 GUI 與全部背景預載。這只是剩餘單欄更新架構的一步，原生全套擷取仍須後續替換，不能先宣稱達成 100 ms。

### 網格重用實作與骨架排序根因

已接入骨骼網格建置入口：256 筆弱參照 LRU，完整建置輸入相同才重用；資產使用 transient package，避免透過 Outer 保留舊角色及其原生 Session。不同角色仍有獨立元件／材質／姿勢。

R20／R21 新測試確認同一 Session 命中、資料變更失效與弱參照回收，但獨立 Session 未命中。逐欄比較定位為原生 skel_export 依 HashMap 子樹遍歷輸出不同骨架／bone_idx。已改匯出專用固定父先順序，使用原作 sibling_index，舊快照缺少該欄時依名稱及來源 id 穩定排序。來源骨架、蒙皮對應及持久格式均保留，不改全域動畫／物理的子樹遍歷。

EditorExportTreeStableR22 一項通過；EditorExportDeterminismR22 實卡一項通過，四次獨立快取讀回的全部骨架／參考 TRS／蒙皮索引／參考頂點／法線／切線／morph 完全一致。UE R22 建置、網格快取與 GUI 回歸／嚴格效能仍待結果，不能從原生測試先推論效能達標。
